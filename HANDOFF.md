# VibeWave. Хэнд-офф и техническое задание

## Точка передачи

- Исходный репозиторий — `Slipcast-dev/VibeWave`. Базовый коммит до этой работы — `f01d61c` (ветка `main`).
- Локальный коммит `34232d5` содержит этапы 1–4. Этапы 5–8 входят в следующий локальный коммит ветки `main`.
- Этап 8 выполнен на доступном Intel Mac. Сборка и результаты сохранены. Ручная и аппаратная приёмка перечислены ниже.
- Текущая версия в `VERSION` — `2.0.0`. Локальная сборка этапа 8 имеет ту же версию, но содержит изменения из этого репозитория.
- Работа только локальная. Используй локальную копию с её коммитами. Публикация, обновление GitHub, PR, теги и релизы выходят за рамки задачи.
- После каждого этапа перечисли изменения и проверки, укажи, что осталось, и спроси пользователя о продолжении. При остатке пятичасового лимита **10% или меньше** остановись. Сохрани согласованное состояние и запиши точку продолжения. Проверяй доступный лимит перед длинными операциями. Если среда его не показывает, сообщи об этом пользователю.

### Как устроено

- `VibeWaveCore` содержит модели, файловые форматы, хранение и правила. `VibeWave` связывает SwiftUI/AppKit, модель плеера и системные API. Минимум — macOS 13 и Swift 5.8. Нужны сборки для `arm64` и `x86_64`. Текущая версия проекта не использует сторонние зависимости.
- `PlayerModel` работает на главном потоке. `MediaScanner` открывает файлы через `AVAudioFile` в фоне. `AudioEngine` планирует сегменты или смежные PCM-буферы. ReplayGain применяется перед сведением и EQ, а баланс и общая громкость — в микшере.
- Запись тегов готовит копию на том же томе и переносит аудиопоток без перекодирования. Перед заменой проверяются структура копии и признаки изменения исходника. Неизвестные кадры MP3 и блоки FLAC сохраняются. Пакетная отмена действует между файлами, сохраняя уже успешные операции.
- `library.json` хранит плейлисты, папки, порядок и правила умных списков. Старые JSON читаются с прежними значениями. У старых записей без даты добавления поле остаётся пустым. `listening.json` рядом с ним хранит оценки, события, счётчики и последнюю дату по пути файла. Файлы лежат в `~/Library/Application Support/VibeWave/`. Настройки хранятся в `UserDefaults`.
- `PlayerModel+Search.swift` индексирует теги и пересчитывает выдачу в фоне. После записи тегов или пересканирования папки индекс затронутых файлов сбрасывается. Очередь, запущенная из выдачи, использует `PlaybackSource.snapshot`.
- Настройки открываются через `⌘,`. Доступны «Общие», «Звук», «Медиатека», «Метаданные и обложки», «Горячие клавиши» и «Обновления». Снимок сеанса хранится в `playback-session.json` рядом с библиотекой. Глобальные привязки хранятся в UserDefaults. Carbon регистрирует выбранные сочетания, MediaPlayer передаёт системные медиакоманды.

### Что проверено и какие границы остались

- Регрессионный набор прошёл на Intel macOS 13.7.8 со Swift 5.8.1. Проверены импорт и экспорт всех трёх типов списков, кириллица и перенос относительных путей, запись тегов и обложек на копиях MP3/FLAC, побайтовая сохранность аудио и неизвестных метаданных, оценки, история, поиск и умные списки. На этапе 5 также проверены реальные кодеки, перемотка и автоматические переходы, чтение тегов MPEG-4, локализованные ошибки и ассоциации Finder.
- Этап 6 проверен по выходному PCM и в модели плеера. Проверки ядра покрыли расчёт ReplayGain, отмену, целостность MP3/FLAC после записи тегов и перенос пресетов. Полный XCTest требует Xcode.
- Этап 7 проверен на Intel. Регрессия покрыла сохранение привязок, конфликты Carbon, освобождение сочетаний после отключения, восстановление сеанса и ручную проверку обновлений с тестовым серверным ответом. Отдельный прогон подтвердил доставку сочетания неактивному тестовому процессу при сохранении фокуса другого приложения. Физические медиаклавиши и Пункт управления входят в ручную приёмку.
- Этап 8 прошёл 21 регрессионную проверку на Intel с macOS 13.7.8. Отдельная тестовая копия приложения перенесла плейлист с двумя треками из Tiho и сохранила импорт M3U8 с относительными путями через системное открытие файлов macOS.
- Переходы и сведение AAC/M4A, ALAC/M4A, FLAC, Opus/CAF, AAC/ADTS и PCM WAV совпали отсчёт в отсчёт с расчётом по независимо декодированному сигналу. Проверены повтор AAC, стык MP3 на беззвучных файлах, очередь из 12 MP3 и отказ следующего файла. В AAC/ADTS сохраняется заполнение декодера.
- У `dist/VibeWave-Stage-8.app` проверена подпись ad hoc. Исполняемый файл содержит `x86_64` и `arm64`. Запуск `arm64` требует Apple Silicon.
- Воспроизведение поддерживает локальные форматы из [матрицы](DOCUMENTATION.md#61-внешние-файлы). Сетевые потоки и HLS не входят в импортируемую медиатеку. Экспорт списка записывает пути и сведения о треках.
- Теги MP3 записываются в обычные ID3v2.3/v2.4 без глобальных флагов. ID3v1 читается, если ID3v2 отсутствует. Для FLAC используются Vorbis Comment и PICTURE в стандартном контейнере. Экзотические или повреждённые структуры отклоняются. Для добавления обложки подходят JPEG/PNG до 12 МиБ с проверкой размеров.
- «Ручной порядок» в фильтре сохраняет порядок раздела, даже если задана сортировка в настройках. Для наследования настройки выбирай «По настройкам поиска».

## Что осталось и как реализовать

### Форматы за пределами нативного этапа

Дополнительные декодеры оценены в [документации](DOCUMENTATION.md#61-внешние-файлы). Для Ogg/Vorbis, Opus в Ogg, WMA, APE, WavPack, Musepack, DSF/DFF, MOD/XM/IT/S3M и MIDI потребуется отдельная интеграция. При проектировании следующего тракта полезно выделить интерфейс порционного чтения PCM и перемотки. Текущие подтверждённые контейнеры и поддержка тегов приведены в матрице.

### Границы обработки звука

- Бесшовность и линейное сведение проверяй на PCM одинакового формата. При расширении на разные форматы потребуется конвертация в общий формат графа и проверка задержки кодеков. Новый случайный цикл повтора очереди выбирается при завершении трека и начинается обычным переходом.
- Для анализа поддерживаются моно и стерео. ReplayGain читается и записывается в MP3/FLAC. Пиковая защита использует отсчёты PCM. При проверке других файлов учитывай задержку и заполнение конкретного кодека.

### Оставшиеся проверки на оборудовании

- На Apple Silicon запусти нативную сборку и повтори проверки из [docs/TESTING.md](docs/TESTING.md). Запусти `swift test` с полным Xcode. На Intel с Command Line Tools отдельный набор XCTest блокируется отсутствием SDK PlatformPath.
- В работающем плеере проверь смену физического аудиовыхода, медиаклавиши клавиатуры и управление из Пункта управления. Для ручной проверки окон пройди сценарии настроек, назначения сочетания, диалогов плейлиста и редактора тегов. При локальной приёмке служба управления интерфейсом macOS не запустилась. Модель, системное открытие файла и программные проверки окон отработали.

## Как перенести и продолжить

Для другого каталога скопируй папку проекта вместе со скрытым каталогом `.git`. Для передачи одним Git-файлом создай архив и клонируй его из нового места. Ветка снимка — `main`.

```sh
# В корне сохранённого репозитория
git status --short
git log -1 --oneline
git bundle create ../VibeWave-local.bundle main
git bundle verify ../VibeWave-local.bundle

# В каталоге назначения. Подставь фактический путь к архиву
git clone --branch main /путь/VibeWave-local.bundle VibeWave
cd VibeWave
```

Git хранит исходники и документацию. Для переноса уже собранного приложения отдельно скопируй `dist/VibeWave-Stage-8.app`. Личные плейлисты и историю переноси только при необходимости. Ссылки на музыку зависят от её путей на диске.

На Mac с Xcode или Command Line Tools открой корень проекта и выполни:

```sh
zsh scripts/check.sh
# Если установлен полный Xcode:
swift test

# Универсальная сборка
zsh scripts/build-app.sh
lipo -archs dist/VibeWave.app/Contents/MacOS/VibeWave
codesign --verify --strict dist/VibeWave.app
open dist/VibeWave.app
```

Если в ограниченной среде тесты падают при создании `AVAudioPlayerNode` с `comp != nullptr`, запусти их в обычной локальной сессии macOS с Core Audio. Если `iconutil` отклоняет корректный набор иконок только в ограниченной среде, повтори упаковку в обычной сессии. На машине с одними Command Line Tools `swift test` не прошёл из-за отсутствующего SDK PlatformPath. Для этапов 3–8 проверенный исполняемый файл регрессий и оба среза были собраны напрямую через `swiftc`.
