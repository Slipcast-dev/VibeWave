### Как устроено

- `VibeWaveCore` содержит модели, файловые форматы, хранение и правила. `VibeWave` связывает SwiftUI/AppKit, модель плеера и системные API. Минимум — macOS 13 и Swift 5.8. Нужны сборки для `arm64` и `x86_64`. Текущая версия проекта не использует сторонние зависимости.
- `PlayerModel` работает на главном потоке. `MediaScanner` открывает файлы через `AVAudioFile` в фоне. `AudioEngine` использует `AVAudioPlayerNode → AVAudioUnitEQ → микшер`. Текущая реализация запускает следующий файл после завершения предыдущего.
- Запись тегов готовит копию на том же томе и переносит аудиопоток без перекодирования. Перед заменой проверяются структура копии и признаки изменения исходника. Неизвестные кадры MP3 и блоки FLAC сохраняются. Пакетная отмена действует между файлами, сохраняя уже успешные операции.
- `library.json` хранит плейлисты, папки, порядок и правила умных списков. Старые JSON читаются с прежними значениями. У старых записей без даты добавления поле остаётся пустым. `listening.json` рядом с ним хранит оценки, события, счётчики и последнюю дату по пути файла. Файлы лежат в `~/Library/Application Support/VibeWave/`. Настройки хранятся в `UserDefaults`.
- `PlayerModel+Search.swift` индексирует теги и пересчитывает выдачу в фоне. После записи тегов или пересканирования папки индекс затронутых файлов сбрасывается. Очередь, запущенная из выдачи, использует `PlaybackSource.snapshot`.
- Настройки открываются через `⌘,`. Уже есть разделы «Воспроизведение», «Плейлисты», «История» и «Поиск треков». Для новых элементов добавляй строки на русском и английском в `Localization.swift`.

### Что проверено и какие границы остались

- Регрессионный набор прошёл на Intel macOS 13.7.8 со Swift 5.8.1. Проверены импорт и экспорт всех трёх типов списков, кириллица и перенос относительных путей, запись тегов и обложек на копиях MP3/FLAC, побайтовая сохранность аудио и неизвестных метаданных, оценки, история, поиск и умные списки.
- `dist/VibeWave-Stage-4.app` — последняя локальная сборка. Подпись ad hoc проверена, в исполняемом файле есть оба среза. Нативный запуск на Apple Silicon и визуальная проверка новых окон не проводились.
- Воспроизведение пока ограничено локальными MP3 и FLAC. Сетевые потоки и HLS не входят в импортируемую медиатеку. Экспорт списка записывает пути и сведения о треках.
- Теги MP3 записываются в обычные ID3v2.3/v2.4 без глобальных флагов. ID3v1 читается, если ID3v2 отсутствует. Для FLAC используются Vorbis Comment и PICTURE в стандартном контейнере. Экзотические или повреждённые структуры отклоняются. Для добавления обложки подходят JPEG/PNG до 12 МиБ с проверкой размеров.
- В текстовом поиске сортировка из настроек подставляется, когда в фильтре нет явного поля сортировки. Если она включена, выбор «Ручной порядок» в фильтре приводит к подстановке значения по умолчанию. При доработке раздела раздели состояния «по умолчанию» и «ручной порядок».

## Что осталось и как реализовать

### Этап 5. Форматы и кодеки

1. Проверь текущие ограничения в `Track.accepts`, `MusicFiles`, `PlayerModel+Import`, `PlaylistExchange`, `MediaScanner`, `AudioEngine`, `AudioMetadataFile` и `Info.plist`. Зафиксируй тестами обычные входы MP3/FLAC перед заменой списков расширений.
2. Создай единый реестр форматов и возможностей. Используй его в диалоге выбора, открытии через Finder, drag-and-drop, обходе папок, проверке записей плейлиста и настройках. Расширение отбирает кандидатов. Поддержку подтверждает декодер при открытии файла.
3. Начни с нативного декодирования WAV/PCM, AIFF/AIF, AAC, M4A (AAC и ALAC), CAF и AU. Проверяй варианты контейнеров на macOS 13 по реальным фикстурам. Сохрани интерфейс управления движком, перемотку, баланс, эквалайзер и уведомление о завершении.
4. Для Ogg Vorbis, Opus, WMA, APE, WavPack, Musepack, DSF/DFF, MOD/XM/IT/S3M и MIDI оцени подходящие декодеры, лицензии, воспроизводимую сборку и доставку обеих архитектур. Для DSD опиши преобразование, для MIDI — синтез и банк звуков. Если добавляется зависимость, зафиксируй версию, способ сборки и условия распространения. Приложение после установки должно работать без инструментов разработчика и без сети.
5. Подготовь матрицу по каждому проверенному формату и кодеку. Колонки — воспроизведение, перемотка, чтение тегов, запись тегов, обложки и ReplayGain. У новых форматов воспроизведение и редактирование тегов могут иметь разный статус. Для файла с неизвестным кодеком, повреждённого или защищённого файла выводи понятную ошибку.
6. Обнови документацию и раздел медиатеки в настройках. Для каждого заявленного семейства проверь импорт, воспроизведение, перемотку и переход к следующему треку. Оформи частичную поддержку явно. Объём «все аудиоформаты» измеряется подтверждённым охватом, включая список оставшихся исключений.

### Этап 6. Обработка звука и переходы

- **ReplayGain.** Читай значения трека и альбома, добавь фоновый анализ с отменой. Сохраняй результат локально. Отдельная команда записывает теги. Добавь режимы «выключен», «трек» и «альбом», предусиление, политику отсутствующих значений и защиту от клиппинга.
- **Бесшовное воспроизведение.** Предварительно готовь следующий файл. Перейди от загрузки после `onFinish` к планированию смежных буферов или сегментов. Учитывай задержку кодека, заполнение конца, частоту, каналы и смену устройства. Проверь границу на выходном PCM и документируй подтверждённые комбинации.
- **Плавное сведение.** Реализуй перекрытие двух источников с настраиваемой длительностью и кривой. Определи приоритет при повторах, коротких треках, перемотке, ручном переходе и последовательных треках одного альбома. Дай возможность сохранить бесшовный переход внутри альбома.
- **EQ.** Добавь именованные пользовательские пресеты, переименование, удаление, импорт и экспорт. Проверь сохранение полос и предусиления. Зафиксируй порядок ReplayGain, EQ, лимитера и общей громкости.

### Этап 7. Клавиши и завершение настроек

- Добавь редактор глобальных сочетаний с назначением действия на выбранные клавиши, очисткой, сбросом и проверкой конфликтов. Поддержи транспорт, перемотку, громкость и звук, повтор, перемешивание и показ окна. Проверь работу вне активного приложения, отключение и системные медиаклавиши. Используй минимальные разрешения macOS.
- Доведи разделы «Общие», «Звук», «Медиатека», «Метаданные и обложки», «Горячие клавиши» и «Обновления». В «Общие» включи язык, восстановление очереди и позиции без автоматического старта звука, поведение закрытия окна. В обновлениях используй существующий `Updater` для ручной проверки и управления автоматической проверкой.
- Сохраняй значения, проверяй допустимые диапазоны и добавь сброс по разделам. Проверяй русскую и английскую локализацию, сохранение после перезапуска и применение без остановки воспроизведения там, где это безопасно.

### Этап 8. Приёмка и сборка

Проведи сквозную проверку на старой и новой библиотеках, на Intel и Apple Silicon, включая ручную работу с окнами, медиаклавишами и плейлистами. Проверь целостность аудио после правок, граничные сценарии переходов и матрицу форматов. Обнови README, DOCUMENTATION и CHANGELOG. Подготовь локальную универсальную сборку и укажи, что проверено фактически. Публикация в этот этап не входит.

## Как перенести и продолжить

Для другого каталога скопируй папку проекта вместе со скрытым каталогом `.git`. Для передачи одним Git-файлом создай локальный архив и клонируй его из нового места. Ветка снимка — `main`.

```sh
# В корне сохранённого репозитория
git status --short
git log -1 --oneline
git bundle create ../VibeWave-local.bundle main
git bundle verify ../VibeWave-local.bundle

# В каталоге назначения. Подставь фактический путь к архиву
git clone --branch main /путь/VibeWave-local.bundle VibeWave
cd VibeWave
```

Git хранит исходники и документацию. Для переноса уже собранного приложения отдельно скопируй `dist/VibeWave-Stage-4.app`. Личные плейлисты и историю переноси только при необходимости. Ссылки на музыку зависят от её путей на диске.

На Mac с Xcode или Command Line Tools открой корень проекта и выполни:

```sh
zsh scripts/check.sh
# Если установлен полный Xcode:
swift test

# Универсальная сборка
zsh scripts/build-app.sh
lipo -archs dist/VibeWave.app/Contents/MacOS/VibeWave
codesign --verify --strict dist/VibeWave.app
open dist/VibeWave.app
```

Если в ограниченной среде тесты падают при создании `AVAudioPlayerNode` с `comp != nullptr`, запусти их в обычной локальной сессии macOS с Core Audio. Если `iconutil` отклоняет корректный набор иконок только в ограниченной среде, повтори упаковку в обычной сессии. На машине с одними Command Line Tools `swift test` не прошёл из-за отсутствующего SDK PlatformPath. Для этапов 3–4 проверенный исполняемый файл регрессий и оба среза были собраны напрямую через `swiftc`.
