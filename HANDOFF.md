### Как устроено

- `VibeWaveCore` содержит модели, файловые форматы, хранение и правила. `VibeWave` связывает SwiftUI/AppKit, модель плеера и системные API. Минимум — macOS 13 и Swift 5.8. Нужны сборки для `arm64` и `x86_64`. Текущая версия проекта не использует сторонние зависимости.
- `PlayerModel` работает на главном потоке. `MediaScanner` открывает файлы через `AudioPCMSource` (`AVAudioFile` или `OggAudioSource`) в фоне. `AudioEngine` планирует сегменты `AVAudioFile` или смежные PCM-буферы. ReplayGain применяется перед сведением и EQ, а баланс и общая громкость — в микшере.
- Запись тегов готовит копию на том же томе и переносит аудиопоток без перекодирования. Перед заменой проверяются структура копии и признаки изменения исходника. Неизвестные кадры MP3 и блоки FLAC сохраняются. Пакетная отмена действует между файлами, сохраняя уже успешные операции.
- `library.json` хранит плейлисты, папки, порядок и правила умных списков. Старые JSON читаются с прежними значениями. У старых записей без даты добавления поле остаётся пустым. `listening.json` рядом с ним хранит оценки, события, счётчики и последнюю дату по пути файла. Файлы лежат в `~/Library/Application Support/VibeWave/`. Настройки хранятся в `UserDefaults`.
- `PlayerModel+Search.swift` индексирует теги и пересчитывает выдачу в фоне. После записи тегов или пересканирования папки индекс затронутых файлов сбрасывается. Очередь, запущенная из выдачи, использует `PlaybackSource.snapshot`.
- Настройки открываются через `⌘,`. Доступны «Общие», «Звук», «Медиатека», «Метаданные и обложки», «Горячие клавиши» и «Обновления». Снимок сеанса хранится в `playback-session.json` рядом с библиотекой. Глобальные привязки хранятся в UserDefaults. Carbon регистрирует выбранные сочетания, MediaPlayer передаёт системные медиакоманды.

Экзотические или повреждённые структуры отклоняются. Для добавления обложки подходят JPEG/PNG до 12 МиБ с проверкой размеров.

## Исправления после анализа (11 ноября 2026)

- **Обновления.** `VERSION` — 2.1.0, поэтому публичный 2.0.x не предлагается как обновление. `VIBEWAVE_UPDATES=off zsh scripts/build-app.sh` удаляет `VWUpdateFeedURL` и `VWUpdatePublicKey` из собранного `Info.plist`: Updater не создаётся. `package-release.sh` такую сборку не упакует — релиз всегда с автообновлением.
- **Запись вне главного потока.** `Sources/VibeWave/PersistenceQueue.swift` — последовательная фоновая очередь. `PlayerModel.save()` и `saveListeningActivity` собирают снимок на главном потоке и пишут его в фоне; ещё не начатая запись того же файла заменяется новой. `PersistenceQueue.shared.flush()` вызывается в `PlayerModel.init` перед чтением и в `applicationWillTerminate`. Ошибки записи по-прежнему показываются в интерфейсе. Снимок сеанса и `UserDefaults` остались синхронными: они маленькие.
- **ReplayGain.** `AudioEngine` кэширует теги ReplayGain текущего файла по адресу и дате изменения: `configurePlayback` при каждом изменении очереди больше не читает файл. Открытие файлов потоком переходов и раньше шло в фоне (`produce` на `decodeQueue`).
- **Sendable.** `ImportJob`, `MediaScanner.Counter`, `DroppedFileBatch` и `LevelMeter` переведены на `OSAllocatedUnfairLock` и проверяемый компилятором `Sendable`. `@unchecked` остался только у `AudioTransitionStream`, `AudioSourceFeeder` и `Chunk` (внутри источник PCM/`AVAudioPCMBuffer`); инвариант доступа описан в комментарии.
- **Тесты.** Добавлены `ShuffleOrderTests`, `PlaylistFileTests` и `LibraryQueryTests`: 17 новых тестов, всего 37.

## Что осталось и как реализовать

### Открытое требование исходного ТЗ по аудиоформатам

Пользователь просил расширить поддержку до всех аудиоформатов. Расширение идёт этапами. Перед каждым этапом опиши конкретные добавляемые контейнеры и кодеки, зависимости и критерии приёмки. Сторонние библиотеки добавляй только с согласия пользователя.

**Этап 9 — Ogg Opus и Ogg Vorbis (выполнен 11 ноября 2026, выпущен в 2.1.0).** Подробности и ограничения — в [матрице](DOCUMENTATION.md#61-внешние-файлы), устройство — в `docs/ARCHITECTURE.md`, фикстуры — в `docs/TESTING.md`.

- Ключевые находки на macOS 27.2.1. `AVAudioFile` открывает Ogg, но у Vorbis сдвигает звук на 464 кадра и отдаёт меньше заявленной длины. На macOS 13.7.8 он Ogg не открывал. Поэтому Ogg всегда идёт собственным трактом. `AVAudioConverter` не декодирует отдельные пакеты Vorbis, поэтому используется C API `AudioConverterFillComplexBuffer`. Системный декодер Vorbis требует длительность каждого пакета (`mVariableFramesInPacket`), без неё молчит. Системный декодер Opus сам срезает первые 120 кадров. Повторное обращение к `AVAudioPCMBuffer.mutableAudioBufferList` сбрасывает `mDataByteSize`.
- Для фикстур Vorbis локально установлен `vorbis-tools` (Homebrew, только для разработки). Приложение его не использует.
- Проверено 11 ноября 2026 на Apple Silicon (macOS 27.2.1, Swift 6.4.2): `swift test` — 52/52 (из них 15 `OggTests`). `scripts/check.sh` arm64 — 22/22 в трёх прогонах. x86_64 через Rosetta — 22/22 в шести прогонах из семи. В первом прогоне x86_64 один `waitFor` превысил 10 с; вывод был буферизован, поэтому проверку определить не удалось, и сбой не повторился. Сборка `dist/VibeWave.app` (arm64 + x86_64) пересобрана, её `Info.plist` содержит `.ogg/.oga/.opus` и `org.xiph.ogg-audio`.
- CI на Intel-раннере `macos-15-intel` для выпуска 2.1.0 прошёл: 52 теста, регрессия Ogg Opus/Vorbis (без проверок окна) и упаковка. Значит, системный декодер Vorbis есть в macOS 15 на Intel.
- Не проверено: декодер Vorbis на macOS 13–14. Нужен прогон `swift test` и `scripts/check.sh` на macOS 13; при отсутствии декодера ожидается сообщение «macOS не поддерживает кодек этого файла». Ручная проверка Ogg в окне плеера (Finder, перетаскивание, редактор тегов в режиме чтения) и нажатие «Обновить» в установленной 2.0.0 не выполнялись.
- Ограничения этапа: моно и стерео; первое звено цепочки Ogg; Ogg FLAC и Speex не поддерживаются; запись тегов Ogg не реализована.

Кандидаты следующих этапов:

1. Запись тегов Ogg (перестройка страниц заголовков, CRC, перенос звука без перекодирования) и многоканальные Opus/Vorbis с перестановкой каналов. Без зависимостей.
2. Декодер Vorbis для macOS без системного (`stb_vorbis`, public domain) — только с согласия.
3. WMA, APE, WavPack, Musepack, DSF/DFF, MOD/XM/IT/S3M и MIDI: оценки в [документации](DOCUMENTATION.md#61-внешние-файлы). Новый декодер подключается как `AudioPCMSource` в `AudioPCMSources.open`.

### Границы обработки звука

- Бесшовность и линейное сведение проверяй на PCM одинакового формата. При расширении на разные форматы потребуется конвертация в общий формат графа и проверка задержки кодеков. Новый случайный цикл повтора очереди выбирается при завершении трека и начинается обычным переходом.
- Для анализа поддерживаются моно и стерео. ReplayGain читается и записывается в MP3/FLAC, из Ogg только читается. Пиковая защита использует отсчёты PCM. При проверке других файлов учитывай задержку и заполнение конкретного кодека.

## Как перенести и продолжить

Для другого каталога скопируй папку проекта вместе со скрытым каталогом `.git`. Для передачи одним Git-файлом создай архив и клонируй его из нового места. Ветка снимка — `main`.

```sh
# В корне сохранённого репозитория
git status --short
git log -1 --oneline
git bundle create ../VibeWave-local.bundle main
git bundle verify ../VibeWave-local.bundle

# В каталоге назначения. Подставь фактический путь к архиву
git clone --branch main /путь/VibeWave-local.bundle VibeWave
cd VibeWave
```

Git хранит исходники и документацию. Для переноса последней готовой сборки отдельно скопируй `dist/VibeWave.app` или возьми установщик из релиза на GitHub. Каталоги `dist/` и `.build/` исключены из Git. Git bundle переносит исходники и историю. Сборки и временные журналы передаются отдельно. Личные плейлисты и историю переноси только при необходимости. Ссылки на музыку зависят от её путей на диске.

На Mac с Xcode или Command Line Tools открой корень проекта и выполни:

```sh
zsh scripts/check.sh
# Если установлен полный Xcode:
swift test

# Универсальная сборка
zsh scripts/build-app.sh
lipo -archs dist/VibeWave.app/Contents/MacOS/VibeWave
codesign --verify --strict dist/VibeWave.app
open dist/VibeWave.app
```

Если в ограниченной среде тесты падают при создании `AVAudioPlayerNode` с `comp != nullptr`, запусти их в обычной локальной сессии macOS с Core Audio. Если `iconutil` отклоняет корректный набор иконок только в ограниченной среде, повтори упаковку в обычной сессии. На машине с одними Command Line Tools `swift test` не прошёл из-за отсутствующего SDK PlatformPath. Для этапов 3–8 проверенный исполняемый файл регрессий и оба среза были собраны напрямую через `swiftc`.
