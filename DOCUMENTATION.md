## 1. Назначение и границы проекта

VibeWave — минималистичный проигрыватель локальной музыки в MP3 и FLAC. Он предназначен для воспроизведения файлов и организации вручную созданных плейлистов.

Реализовано:

- воспроизведение, пауза, предыдущий и следующий трек;
- перемотка, регулировка громкости, отображение позиции и длительности;
- последовательное воспроизведение до конца текущей очереди;
- временная очередь вне плейлистов;
- создание, переименование и удаление плейлистов;
- сохранение порядка и состава ручных плейлистов;
- добавление нескольких файлов через диалог и перетаскивание;
- перестановка треков и перенос между плейлистами;
- три темы и собственное оформление окна в стиле Windows 95;
- открытие MP3/FLAC через Finder или значок Dock;
- иконка приложения и локальный Git-репозиторий.

Приложение не содержит аккаунтов, рекламы, сетевых запросов, стриминга, эквалайзера и облачной синхронизации. Оно не копирует музыку в собственную медиатеку и не изменяет исходные аудиофайлы.

## 2. Требования к окружению

| Компонент | Требование |
|---|---|
| Операционная система | macOS 13+ |
| Язык и манифест пакета | Swift 5.8+; `swift-tools-version: 5.8` |
| Средства разработки | Xcode либо Command Line Tools с macOS SDK |
| Сторонние зависимости | Отсутствуют |
| Пакетный менеджер | Swift Package Manager при полном Xcode; есть прямая сборка Swift |
| Поддерживаемые расширения | `.mp3`, `.flac`, без учёта регистра |
| Сеть для работы плеера | Не требуется |
| Секреты и ключи для локальной сборки | Не требуются |

Текущая локальная сборка проверена на x86_64 с Swift 5.8.1 и macOS SDK 13.3. Скрипт использует архитектуру текущего компьютера. Работоспособность отдельной arm64-сборки и универсального пакета должна проверяться перед их распространением; в этом документе такая проверка не заявляется.

Для полного набора XCTest нужен полный Xcode. Для регрессионного сценария проекта достаточно совместимого Command Line Tools.

## 3. Запуск и сборка

### 3.1. Готовое приложение

Папка проекта на текущем компьютере:

```text
$HOME/Desktop/VibeWave
```

Готовое приложение после локальной сборки:

```text
$HOME/Desktop/VibeWave/dist/VibeWave.app
```

Откройте `.app` в Finder либо выполните:

```sh
open "$HOME/Desktop/VibeWave/dist/VibeWave.app"
```

Приложение не устанавливается автоматически в `/Applications`.

### 3.2. Сборка из исходников

```sh
cd "$HOME/Desktop/VibeWave"
zsh scripts/build-app.sh
open dist/VibeWave.app
```

Скрипт выполняет следующие действия:

1. Читает и проверяет номер из `VERSION`.
2. Проверяет наличие исходной иконки.
3. Использует SwiftPM, если установленный комплект Apple предоставляет SDK PlatformPath.
4. При отсутствии PlatformPath компилирует ядро и приложение напрямую через `swiftc`.
5. Создаёт новый временный bundle внутри `dist/`.
6. Копирует исполняемый файл и шаблон `Resources/Info.plist`.
7. Записывает версию в `CFBundleShortVersionString` и `CFBundleVersion`.
8. Создаёт размеры иконки и ресурс `VibeWaveIcon.icns`.
9. Выполняет ad hoc подпись и проверяет её.
10. Заменяет прежний сгенерированный `.app` и удаляет временную упаковку.

Обработчик завершения очищает временный каталог, в том числе при ошибке. На этапе окончательной замены прежний сгенерированный bundle удаляется, поэтому резервную копию нужного релиза следует сохранить отдельно заранее.

Первое построение системных модулей может занимать несколько минут. Повторная сборка использует локальные кеши.

### 3.3. Дополнительные параметры

`VIBEWAVE_MODULE_CACHE` — необязательная переменная с путём к кешу модулей прямого компилятора. Для обычной работы задавать её не нужно. Скрипт использует собственный каталог под `.build/`.

Не переносите готовый кеш модулей простым копированием между разными путями: скомпилированные модули могут содержать привязку к исходному местоположению. При подобных ошибках используйте новый пустой кеш.

`swift run VibeWave` при полном Xcode может использоваться для разработки исполняемого пакета. Для проверки иконки, регистрации файлов и поведения готового приложения используйте собранный `.app`.

## 4. Интерфейс и управление

### 4.1. Элементы окна

| Элемент | Назначение |
|---|---|
| Верхняя полоса `VibeWave` | Перемещение окна; двойной щелчок — развернуть/восстановить |
| Кнопка `_` | Свернуть окно |
| Кнопка с квадратом | Развернуть в доступную область экрана или восстановить размер |
| Кнопка `×` | Закрыть окно, оставив приложение работающим |
| Список «Плейлисты» | Открыть вручную созданный плейлист |
| Кнопка с нотой рядом с `+` | Показать музыку вне плейлистов |
| Кнопка `+` | Создать новый плейлист |
| «Добавить файлы…» | Добавить файлы в текущий выбранный раздел |
| Меню «Тема» | Выбрать одну из трёх тем |
| Центральная таблица | Название, формат и длительность треков |
| Нижние кнопки | Предыдущий трек, воспроизведение/пауза, следующий трек |
| Ползунок позиции | Перемотать текущий трек |
| Ползунок громкости | Изменить громкость плеера |

Повторяющаяся надпись «Открытые файлы» над очередью и отдельная большая кнопка с этой подписью убраны. Название выбранного ручного плейлиста сохраняется в заголовке его списка.

### 4.2. Клавиатура

| Сочетание | Действие |
|---|---|
| `⌘O` | Добавить файлы в текущий раздел |
| `⌘W` | Закрыть окно |
| `⌘M` | Свернуть окно |
| `⌘Q` | Завершить приложение |
| Пробел вне текстового редактора | Воспроизведение/пауза |
| Стрелки при фокусе на ползунке | Изменить его значение |
| `⌘C`, `⌘V`, `⌘X`, `⌘A` в редакторе | Стандартные операции с текстом |

При позиции текущего трека больше трёх секунд кнопка предыдущего трека сначала возвращает его к началу. На первом треке переход назад остаётся в начале очереди. После последнего трека воспроизведение останавливается.

## 5. Очередь и плейлисты

### 5.1. Временная очередь

Очередь предназначена для музыки, которую открыли без добавления в плейлист. Она существует только в памяти процесса.

- При запуске приложение не создаёт плейлист.
- Кнопка с нотой показывает очередь.
- Файлы в ней можно воспроизводить, переставлять и убирать.
- Закрытие окна не завершает приложение и сохраняет очередь в памяти.
- После `⌘Q` очередь не восстанавливается.

Это осознанное разделение: временная музыка не записывается в библиотеку плейлистов.

### 5.2. Ручные плейлисты

1. Нажмите `+`.
2. Введите непустое название и сохраните его.
3. Выберите созданный плейлист.
4. Нажмите «Добавить файлы…» либо перетащите музыку в его список.

Переименование и удаление доступны в контекстном меню плейлиста. Удаление трека из списка также выполняется через контекстное меню. Эти операции не удаляют аудиофайлы с диска.

Пустые названия после удаления пробелов не принимаются. Дубликаты одного нормализованного файлового URL внутри раздела не добавляются. Это проверка пути, а не содержимого файла: одинаковая музыка по разным путям может считаться разными записями.

### 5.3. Назначение операций

| Операция | Результат |
|---|---|
| Добавление при показе очереди | Файлы попадают в очередь |
| Добавление при выбранном плейлисте | Файлы попадают в этот плейлист |
| Открытие из Finder/Dock | Файлы попадают в очередь, начинается воспроизведение первого успешно открытого файла |
| Перетаскивание в список | Добавление в показанный раздел |
| Перетаскивание на название плейлиста | Добавление непосредственно в этот плейлист |
| Перестановка строки внутри раздела | Меняется порядок |
| Перенос между двумя плейлистами | Запись перемещается |
| Добавление из очереди в плейлист | Запись добавляется в плейлист, очередь сохраняется |
| Перенос из плейлиста в очередь | Создаётся запись в очереди; исходный плейлист сохраняется |

Если целевой плейлист уже содержит тот же файл, исходная запись не удаляется. При удалении назначения во время фонового импорта появляется сообщение; новый плейлист вместо удалённого не создаётся.

Просмотр раздела и фактическое воспроизведение разделены. Переключение между плейлистами само по себе не переключает текущий трек.

## 6. Открытие и перетаскивание файлов

### 6.1. Внешние файлы

Поддерживаются локальные MP3 и FLAC. Обычный путь:

```text
Finder / файловый диалог → URL → проверка формата → декодер → очередь или плейлист
```

Перетаскивание работает через `NSItemProvider`. Внешние адреса загружаются как `public.file-url`. Порядок результатов сохраняется, даже если отдельные providers завершили загрузку в разное время.

Одновременно выполняется один импорт. Во время добавления повторные действия ограничиваются; следует дождаться завершения текущей операции.

Открытие файлов через Finder/Dock зарегистрировано в `Info.plist`. Ранг обработчика `Alternate` не назначает VibeWave проигрывателем по умолчанию автоматически.

### 6.2. Внутренние переносы

Для строки внутри приложения используется собственный тип `local.vibewave.track`. Payload содержит идентификатор исходного раздела и трека.

Тип проверяется точным совпадением в `registeredTypeIdentifiers`. Одного широкого запроса SwiftUI по совместимости типа недостаточно: ранее он приводил к направлению обычного MP3/FLAC в обработчик внутренних JSON-данных.

Чтобы поставить трек перед другим, перетащите его на нужную строку. Чтобы переместить в конец — в нижнюю свободную область списка.

## 7. Темы и окно

### 7.1. Палитры

| Тема | Оформление |
|---|---|
| Windows 95 | Серые панели, белые списки, тёмно-синие заголовок и выделение |
| Светлая | Чёрно-белая палитра с светлыми панелями |
| Тёмная | Тёмные поверхности и фиолетовые элементы |

Во всех темах общая ретро-геометрия: квадратные элементы, объёмные грани, эффект нажатия, вдавленные поля и прямоугольные бегунки. Выбор сохраняется через `AppStorage`.

При первом включении ретро-оформления выбирается Windows 95. В дальнейшем применяется сохранённый выбор пользователя.

### 7.2. Собственное окно

Приложение использует borderless-окно AppKit. Стандартной полосы с красной, жёлтой и зелёной кнопками нет. Вместо неё работает собственный заголовок с настоящими `NSButton`.

- Начальный размер — 900 × 570 точек.
- Минимальный размер содержимого — 720 × 440 точек.
- Окно может стать key/main, поэтому поддерживается ввод с клавиатуры.
- Размер и положение сохраняются механизмом frame autosave с именем `VibeWaveMainWindow`.
- Если восстановленное окно не пересекает доступные экраны, оно центрируется.
- Разворачивание использует доступную область текущего экрана, а не фиксированное разрешение.
- Повторное нажатие значка Dock показывает закрытое или свёрнутое окно.

Файловый диалог, системное меню приложения и контекстные меню остаются нативными macOS.

## 8. Данные, настройки и резервное копирование

### 8.1. Расположение

| Данные | Место хранения |
|---|---|
| Ручные плейлисты | `~/Library/Application Support/VibeWave/library.json` |
| Прежняя библиотека | `~/Library/Application Support/Tiho/library.json` |
| Тема и положение окна | Стандартные настройки macOS для `local.vibewave.player` |
| Временная очередь | Только оперативная память процесса |
| Исходная музыка | Исходные пользовательские папки |
| Производные сборки | `dist/` |
| Кеши разработки | `.build/` |

Библиотека находится вне папки исходников. Очистка проекта и замена `.app` сами по себе её не удаляют.

### 8.2. Сохранение и миграция

Плейлисты записываются автоматически после изменения. Запись выполняется атомарно, чтобы не оставлять частично записанный JSON.

Если новой библиотеки ещё нет, приложение пробует прочитать прежнюю библиотеку «Тихо». Существующие плейлисты переносятся, исходный файл не изменяется. Если библиотека повреждена, приложение сообщает об ошибке и блокирует её молчаливую перезапись.

Ссылки на файлы могут сопровождаться security-scoped закладками. Если механизм недоступен, для локальной сборки достаточно обычного URL. Это не переносит и не копирует музыку.

### 8.3. Резервная копия

Для сохранения пользовательской коллекции:

1. Дождитесь окончания импорта.
2. Завершите приложение.
3. Скопируйте `library.json` в отдельную папку с датой.
4. Отдельно сохраните сами аудиофайлы: JSON содержит ссылки, а не звук.

Перед восстановлением сначала сохраните текущий `library.json`, даже если он повреждён. Возвращайте резервную копию при закрытом приложении.

Для резервирования разработки сохраняйте Git-репозиторий с ресурсами. Git сохраняет историю изменений. Приватный remote содержит опубликованные исходники; он не заменяет резервирование пользовательской библиотеки и музыки.

## 10. Архитектура и потоки данных

### 10.1. Слои

| Слой | Компоненты | Ответственность |
|---|---|---|
| Ядро | `VibeWaveCore` | Модели, библиотека, перестановка, форматирование |
| Состояние приложения | `PlayerModel` | Импорт, выбор раздела, воспроизведение, сохранение |
| Интерфейс | `ContentView`, `TrackRow`, `Theme`, `RetroControls` | Представление и пользовательские действия |
| Платформа | `VibeWaveApp`, `RetroWindow` | NSApplication, окно, меню, Dock, файловые события |
| Сборка и контроль | `scripts`, `Checks`, `Tests` | Упаковка и проверки |

Ядро не зависит от SwiftUI и аудиодекодера. Интерфейс обращается к модели, а не записывает JSON самостоятельно.

### 10.2. Жизненный цикл

```text
VibeWaveApp.main
  → NSApplication
  → VibeWaveAppDelegate
  → один PlayerModel
  → один RetroWindowController
  → NSHostingView(ContentView)
```

Делегат устанавливает иконку, создаёт меню и показывает окно. Он удерживает контроллер окна, чтобы закрытое окно можно было показать повторно. При завершении приложения аудиопроигрыватель останавливается.

### 10.3. Состояние модели

- `playlists` — сохранённые ручные списки.
- `openTracks` — временная очередь.
- `selectedID` — выбранный плейлист; `nil` означает очередь.
- `visibleTracks` — содержимое текущего раздела.
- `current`, `playing`, `position`, `duration`, `volume` — состояние проигрывания.
- `queue`, `playbackPlaylistID` — источник последовательного воспроизведения.
- `importing`, `error` — состояние длительной операции и пользовательское сообщение.

Назначение импорта фиксируется до фоновой работы. Переключение раздела во время импорта не направляет файлы в другой плейлист.

### 10.4. Потоки

Декодирование импортируемых файлов выполняется последовательно на фоновой очереди. Изменения наблюдаемого состояния возвращаются на главный поток. Загрузка нескольких providers синхронизируется через `DispatchGroup`, а доступ к результатам защищается `NSLock`.

Воспроизведение и пользовательские действия управляются моделью. При паузе периодический таймер позиции отключается; во время проигрывания позиция обновляется с интервалом 0,25 секунды.

## 11. Модели и формат библиотеки

### 11.1. Типы

| Тип | Основные поля |
|---|---|
| `Track` | `id: UUID`, `url: URL`, `bookmark: Data?`, `title: String`, `duration: TimeInterval` |
| `Playlist` | `id: UUID`, `name: String`, `tracks: [Track]` |
| `TrackDragPayload` | `playlistID: UUID?`, `trackID: UUID` |
| `LibraryStore` | URL файла библиотеки; методы `load()` и `save()` |

Название трека берётся из имени файла без расширения. Длительность — из декодера. Метаданные исполнителя и альбома в текущем интерфейсе не извлекаются.

### 11.2. JSON

Верхний уровень — массив плейлистов. Пример ниже иллюстративный, не содержит пользовательских данных:

```json
[
  {
    "id": "11111111-1111-4111-8111-111111111111",
    "name": "Вечер",
    "tracks": [
      {
        "id": "22222222-2222-4222-8222-222222222222",
        "url": "file:///Users/example/Music/Track.flac",
        "title": "Track",
        "duration": 258
      }
    ]
  }
]
```

При наличии `bookmark` Codable записывает данные как Base64-строку. Отсутствующее необязательное поле допустимо. Версия приложения не является отдельным полем схемы JSON; при будущем изменении схемы потребуется явная совместимая миграция.

## 12. Аудиовоспроизведение и обработка ошибок

Для текущего трека создаётся `AVAudioPlayer`. Он получает громкость, делегат завершения и URL исходного файла. При смене трека прежний проигрыватель останавливается, а ранее открытый security-scoped доступ закрывается.

Ошибка декодирования, недоступный файл или невозможность воспроизведения превращаются в сообщение пользователю. При частично успешном импорте исправные файлы добавляются, а проблемные перечисляются с причинами отказа.

Во время импорта имя с расширением MP3/FLAC не считается достаточным доказательством исправности: файл пробует открыть аудиодекодер. URL из сети не принимаются как локальная музыка.

Перемотка ограничивается диапазоном от нуля до длительности. После успешного окончания трека модель выбирает следующий; ошибка декодирования во время воспроизведения останавливает его и показывает сообщение.

## 13. Иконка и упаковка приложения

Исходная иконка — `Assets/AppIcon.png`: фиолетовая волна на тёмной скруглённой плитке с прозрачностью снаружи.

Скрипт создаёт размеры 16, 32, 128, 256 и 512 пикселей и варианты `@2x`, затем собирает `VibeWaveIcon.icns` через `iconutil`. Ресурс включается в `Contents/Resources/`, а `CFBundleIconFile` указывает на его имя.

Приложение также явно устанавливает изображение через `NSApplication.applicationIconImage` и именованную иконку AppKit. Это устраняет зависимость работающего Dock-значка от прежнего стандартного изображения в кеше.

`Resources/Info.plist` — шаблон. `VERSION` — единственный источник номера релиза. В шаблоне служебные номера заменяются скриптом при упаковке.

## 15. Безопасность и конфиденциальность

- У приложения нет сетевых функций и необходимости в API-ключах.
- В библиотеку записываются пути к музыке и названия плейлистов. Это пользовательские данные: не публикуйте `library.json` без проверки содержимого.
- Исходная музыка не удаляется и не перезаписывается операциями библиотеки.
- Локальная версия работает без App Sandbox. Это фактическая конфигурация сборки, а не инструкция отключать защиту macOS.
- Для публичной сборки права доступа и entitlements необходимо проверить отдельно.
- Секреты подписи и учётные данные Developer Program нельзя хранить в исходниках, Markdown-файлах или Git.
- `.gitignore` исключает `.env`, локальные настройки, кеши и сборки.
- Перед изменением пользовательской библиотеки, очисткой исходников или миграцией сохраняется резервная копия.

## 16. Устранение неполадок

| Симптом | Проверка и действие |
|---|---|
| Файл не добавляется | Проверить локальный путь, расширение и возможность чтения; изучить причину в сообщении импорта. Проверить, выбран ли нужный раздел |
| Появляется сообщение о внутреннем треке при внешнем файле | Убедиться, что запущена актуальная сборка; проверить точное определение типа в `DropReceiver` и регрессионный путь providers |
| `Failed to retrieve app-scope key` | Закладка в локальной сборке должна оставаться необязательной; её ошибка не должна отклонять исправный аудиофайл |
| Файл переместили или удалили | Добавить его заново из актуального местоположения; не изменять JSON наугад |
| Нет звука | Проверить громкость плеера, системный выход и доступность аудиоустройства; проверить другой исправный файл |
| Очередь исчезла после завершения | Ожидаемое поведение; для постоянного хранения создать плейлист |
| Нет окна после нажатия крестика | Нажать значок приложения в Dock; закрытие окна не завершает процесс |
| Видна старая версия интерфейса | Завершить старую копию и открыть именно `dist/VibeWave.app` из текущего проекта |
| Стандартный значок вместо иконки | Проверить наличие `VibeWaveIcon.icns`, запись `CFBundleIconFile`, подпись bundle и запуск текущей сборки |
| SwiftPM сообщает об отсутствующем PlatformPath | Запускать `scripts/build-app.sh`; он использует прямую сборку. Для XCTest установить полный Xcode |
| Ошибка пути PCH/module cache | Использовать новый кеш по стабильному пути; не копировать кеш между каталогами |
| Иконка не упаковывается | Проверить исходный PNG, размеры iconset и ошибку `iconutil`; не распространять частично собранный bundle |
| Библиотека не читается | Сохранить проблемный JSON отдельно, проверить резервную копию. Приложение намеренно не перезаписывает повреждённые данные |

Не отключайте SIP, Gatekeeper или проверку подписи для устранения этих ошибок.

## 18. Подготовка релиза и откат

### 18.1. Локальный релиз

Текущий сценарий готовит локальный `.app`, а не публичный установщик.

1. Проверить изменения и актуальность `VERSION`.
2. Обновить журнал изменений и документацию.
3. Собрать приложение и запустить проверки.
4. Выполнить ручную приёмку.
5. Проверить подпись.
6. Сохранить отдельно нужный предыдущий bundle и пользовательскую библиотеку.
7. Передать проверенную локальную сборку владельцу проекта.

Изменения только Markdown не требуют повышения версии исполняемого приложения.

### 18.2. Публичное распространение — отдельный этап

Для прямого распространения вне Mac App Store следует подготовить Developer ID-подпись, Hardened Runtime, проверенные разрешения и отправку на нотариализацию. Apple предоставляет `notarytool` и `stapler`; ad hoc подпись текущего скрипта не заменяет этот процесс. Требования и порядок подтверждаются по [официальной документации Apple](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution).

План публичного выпуска:

1. Уточнить поддерживаемые архитектуры и канал доставки.
2. Подготовить отдельную конфигурацию подписи и упаковки; не помещать секреты в Git.
3. Проверить сборки на заявленных архитектурах.
4. Настроить Developer ID, Hardened Runtime и необходимые entitlements.
5. Подписать исполняемые компоненты и сформировать распространяемый пакет.
6. Отправить пакет на нотариализацию, проверить результат и журнал.
7. Прикрепить ticket к поддерживаемому артефакту и повторно проверить его.
8. Проверить чистую установку/открытие на другом Mac.
9. Подготовить номер версии, release notes, контрольную сумму и план отката.
10. Публиковать только в явно согласованный канал.

Это план последующего этапа, а не описание уже выполненной публикации. Текущий `build-app.sh` потребуется расширить или дополнить отдельным release-сценарием. Простая повторная локальная сборка снова создаст ad hoc bundle.

### 18.3. Откат

До обновления сохранить прежний проверенный `.app` вне `dist/`, поскольку каталог сборки заменяется. При проблеме завершить текущую версию и открыть сохранённую. Исходники восстанавливать через отдельную ветку или checkout нужного коммита, сохранив незакоммиченные изменения. Не использовать `git reset --hard` как обычный способ отката.

Если менялась схема пользовательских данных, откат приложения допустим только с совместимой библиотекой либо её предварительно сохранённой копией.

## 19. Ограничения и история разработки

### 19.1. Текущие ограничения

- Поддерживаются только локальные MP3/FLAC; каталоги и сетевые потоки не реализованы.
