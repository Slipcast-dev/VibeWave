## 1. Назначение и границы проекта

VibeWave — минималистичный проигрыватель локальной музыки в MP3 и FLAC. Он предназначен для воспроизведения файлов и организации вручную созданных плейлистов.

Реализовано:

- воспроизведение, пауза, стоп, предыдущий и следующий трек;
- перемотка, громкость, баланс каналов, отображение позиции и длительности;
- 10-полосный эквалайзер с предусилением и пресетами;
- табло со временем, бегущей строкой, битрейтом, частотой, моно/стерео и индикатором уровня;
- последовательное и случайное воспроизведение, повтор очереди и трека;
- временная очередь вне плейлистов;
- импорт и экспорт M3U, M3U8 и PLS;
- создание, переименование и удаление плейлистов;
- сохранение порядка и состава ручных плейлистов;
- добавление нескольких файлов через диалог и перетаскивание;
- перестановка треков мышью и перенос между плейлистами;
- раздел «Вся музыка» (общий список с ручным порядком или группировка по плейлистам и папкам);
- папки с музыкой в боковой панели: рекурсивный поиск MP3/FLAC, обновление содержимого, прогресс и отмена;
- оформление окна в стиле Windows 95 с панелью плеера и табло времени;
- интерфейс на русском и английском с выбором по языку системы и ручным переключением;
- открытие MP3/FLAC через Finder или значок Dock;
- автообновление: проверка при запуске, вопрос «Обновить / Позже», фоновая загрузка, проверка подписи, замена и перезапуск;
- иконка приложения, Git-репозиторий и CI на GitHub Actions.

Приложение не содержит аккаунтов, рекламы, стриминга и облачной синхронизации. Единственный сетевой запрос — проверка обновлений на GitHub при запуске и, с согласия пользователя, загрузка обновления. Оно не копирует музыку в собственную медиатеку и не изменяет исходные аудиофайлы.

## 2. Требования к окружению

| Компонент | Требование |
|---|---|
| Операционная система | macOS 13+ |
| Язык и манифест пакета | Swift 5.8+; `swift-tools-version: 5.8` |
| Средства разработки | Xcode либо Command Line Tools с macOS SDK |
| Сторонние зависимости | Отсутствуют |
| Пакетный менеджер | Swift Package Manager при полном Xcode; есть прямая сборка Swift |
| Поддерживаемые расширения | `.mp3`, `.flac`, без учёта регистра |
| Сеть для работы плеера | Не требуется |
| Секреты и ключи для локальной сборки | Не требуются |

Релиз 2.0.0 — **универсальное** приложение (arm64 + x86_64), собранное Swift 6.4.2 с macOS SDK 27.2 в языковом режиме Swift 5. Регрессионные проверки прошли для обеих архитектур на Apple Silicon (x86_64 — через Rosetta), CI собирает и проверяет приложение на Intel-раннере. Запуск на физическом Intel-Mac и сборка самым старым заявленным компилятором Swift 5.8 не проверялись. Переменная `VIBEWAVE_ARCHS` ограничивает сборку нужными архитектурами.

Для полного набора XCTest нужен полный Xcode. Для регрессионного сценария проекта достаточно совместимого Command Line Tools.

## 3. Запуск и сборка

### 3.1. Готовое приложение

Готовое приложение после локальной сборки находится в каталоге проекта:

```text
dist/VibeWave.app
```

Откройте `.app` в Finder либо выполните из каталога проекта:

```sh
open dist/VibeWave.app
```

Приложение не устанавливается автоматически в `/Applications`. Установщики опубликованы на странице [GitHub Releases](https://github.com/Slipcast-dev/VibeWave/releases).

### 3.2. Сборка из исходников

Из каталога проекта:

```sh
zsh scripts/build-app.sh
open dist/VibeWave.app
```

Скрипт выполняет следующие действия:

1. Читает и проверяет номер из `VERSION`.
2. Проверяет наличие исходной иконки.
3. Для каждой архитектуры (по умолчанию `arm64` и `x86_64`) использует SwiftPM, если установленный комплект Apple предоставляет SDK PlatformPath.
4. При отсутствии PlatformPath компилирует ядро и приложение напрямую через `swiftc`, отдельно для каждой архитектуры. Файлы исходников берутся по маске `Sources/<модуль>/*.swift`.
5. Создаёт новый временный bundle внутри `dist/`.
6. Объединяет срезы через `lipo` в универсальный исполняемый файл, проверяет наличие каждого среза и копирует шаблон `Resources/Info.plist`.
7. Записывает версию в `CFBundleShortVersionString` и `CFBundleVersion`.
8. Создаёт размеры иконки и ресурс `VibeWaveIcon.icns`.
9. Выполняет ad hoc подпись и проверяет её.
10. Заменяет прежний сгенерированный `.app` и удаляет временную упаковку.

Обработчик завершения очищает временный каталог, в том числе при ошибке. На этапе окончательной замены прежний сгенерированный bundle удаляется, поэтому резервную копию нужного релиза следует сохранить отдельно заранее.

Первое построение системных модулей может занимать несколько минут. Повторная сборка использует локальные кеши.

### 3.3. Дополнительные параметры

`VIBEWAVE_ARCHS` — архитектуры сборки через пробел; по умолчанию `arm64 x86_64`. Для быстрой отладки: `VIBEWAVE_ARCHS="$(uname -m)" zsh scripts/build-app.sh`.

`VIBEWAVE_CHECK_ARCH` — архитектура регрессионных проверок; `x86_64` на Apple Silicon запускается через Rosetta.

`VIBEWAVE_MODULE_CACHE` — необязательная переменная с путём к кешу модулей прямого компилятора. Для обычной работы задавать её не нужно. Скрипт использует собственный каталог под `.build/`.

Не переносите готовый кеш модулей простым копированием между разными путями: скомпилированные модули могут содержать привязку к исходному местоположению. При подобных ошибках используйте новый пустой кеш.

`swift run VibeWave` при полном Xcode может использоваться для разработки исполняемого пакета. Для проверки иконки, регистрации файлов и поведения готового приложения используйте собранный `.app`.

## 4. Интерфейс и управление

### 4.1. Элементы окна

Окно состоит из заголовка, панели плеера сверху и плейлиста под ней. Библиотека (плейлисты и папки) открывается слева кнопкой «Библиотека».

| Элемент | Назначение |
|---|---|
| Верхняя полоса `♪ VibeWave` | Перемещение окна; двойной щелчок — развернуть/восстановить |
| Кнопка `_` | Свернуть окно |
| Кнопка с квадратом | Развернуть в доступную область экрана или восстановить размер |
| Кнопка `×` | Закрыть окно, оставив приложение работающим |
| Табло времени | Щелчок переключает прошедшее/оставшееся время |
| Бегущая строка | Номер и название текущего трека |
| Поля kbps / kHz, «моно»/«стерео» | Сведения о текущем файле |
| Индикатор уровня | Уровни левого и правого канала |
| Ползунок громкости | Громкость плеера |
| Ползунок баланса | Баланс каналов; двойной щелчок возвращает в центр |
| Ползунок позиции | Перемотка текущего трека |
| Кнопки ⏮ ▶ ❚❚ ■ ⏭ | Предыдущий, воспроизведение, пауза, стоп, следующий |
| Кнопка **EQ** (справа в том же ряду) | Открыть эквалайзер; надпись синяя, когда он включён |
| Строка плейлиста «N. Название — время» | Щелчок запускает трек; протяжка мышью переставляет строку |
| «+ Файл» | Добавить MP3/FLAC в выбранный плейлист или в музыку вне плейлистов |
| «+ Папка» | Добавить папку с музыкой |
| «Библиотека» | Показать или скрыть боковую панель |
| Меню «Вид ▾» | «Общий список» или «По плейлистам»; переход к разделу; новый плейлист |
| Меню «RU ▾ / EN ▾» | Язык интерфейса: «Как в системе», «Русский», «English» |
| Счётчик справа внизу | Число треков и общее время раздела |
| Ход импорта и «Отмена» | Во время добавления файлов или сканирования папки заменяют счётчик |
| «Вся музыка» в боковой панели | Все треки библиотеки без повторов |
| `+` у «Плейлисты» | Создать плейлист; контекстное меню — переименовать, удалить |
| `+` у «Папки» | Добавить папку; контекстное меню — обновить, показать в Finder, убрать |

### 4.2. Клавиатура

| Сочетание | Действие |
|---|---|
| `⌘O` | Добавить файлы в текущий раздел |
| `⌘,` | Открыть настройки |
| `⌘W` | Закрыть окно |
| `⌘M` | Свернуть окно |
| `⌘Q` | Завершить приложение |
| Пробел вне текстового редактора | Воспроизведение/пауза |
| Стрелки при фокусе на ползунке | Изменить его значение |
| `⌘C`, `⌘V`, `⌘X`, `⌘A` в редакторе | Стандартные операции с текстом |

При позиции текущего трека больше трёх секунд кнопка предыдущего трека сначала возвращает его к началу. При перемешивании переход назад использует фактический порядок прослушивания.

Перемешивание и режим повтора меняются в панели плеера, меню «Воспроизведение» и одноимённом разделе настроек. Выбранные параметры сохраняются между запусками. Случайный порядок проходит по очереди один раз за цикл. При повторе очереди плеер начинает новый цикл, а при повторе трека автоматическое завершение запускает этот же трек заново. Ручная кнопка «Следующий» продолжает очередь даже при повторе трека.

## 5. Очередь и плейлисты

### 5.1. Музыка вне плейлистов и раздел «Вся музыка»

Музыка вне плейлистов — временная очередь для файлов, открытых без добавления в плейлист. Она существует только в памяти процесса.

- При запуске приложение не создаёт плейлист.
- Раздел «Вся музыка» собирает треки из плейлистов, папок и вне плейлистов без повторов одного файла.
- В виде «Общий список» порядок задаётся перетаскиванием и сохраняется (кроме треков вне плейлистов).
- В виде «По плейлистам» треки разбиты на разделы; перетаскивание на раздел переносит или копирует трек туда.
- Треки вне плейлистов можно воспроизводить, переставлять и убирать.
- Закрытие окна не завершает приложение и сохраняет очередь в памяти.
- После `⌘Q` очередь не восстанавливается.

Это осознанное разделение: временная музыка не записывается в библиотеку плейлистов.

### 5.2. Ручные плейлисты

1. Откройте «Библиотека» и нажмите `+` у заголовка «Плейлисты» (или «Вид ▾» → «Новый плейлист…»).
2. Введите непустое название и сохраните его.
3. Выберите созданный плейлист.
4. Нажмите «+ Файл» либо перетащите музыку в его список или на его название в библиотеке.

Переименование и удаление доступны в контекстном меню плейлиста. В контекстном меню трека — источник записи, «Выше»/«Ниже», «Добавить в плейлист» (или «Переместить в плейлист») и удаление из списка. Эти операции не удаляют аудиофайлы с диска.

### 5.3. Папки с музыкой

Папка добавляется кнопкой «+ Папка», `+` у заголовка «Папки» или перетаскиванием каталога из Finder. VibeWave рекурсивно ищет MP3 и FLAC и сортирует их как Finder («Track 2» раньше «Track 10»).

- Учитываются только обычные файлы и символические ссылки на них. Скрытые файлы, каталоги с именем вида `Album.mp3` и содержимое пакетов (`.app`, медиатеки) пропускаются.
- Файлы проверяются аудиодекодером параллельно, по несколько одновременно.
- «Обновить содержимое» сохраняет порядок и ID известных треков, убирает исчезнувшие и добавляет новые в конец. Уже известные файлы повторно не открываются, поэтому обновление большой папки идёт быстро.
- Недоступная папка (отключён диск, нет прав) при обновлении не очищается.
- «Скрыть из папки» убирает запись до следующего обновления: файл остаётся на диске и при обновлении появится снова.
- В папку нельзя перенести трек извне; из папки трек копируется в плейлист.

Пустые названия после удаления пробелов не принимаются. Дубликаты одного нормализованного файлового URL внутри раздела не добавляются. Это проверка пути, а не содержимого файла: одинаковая музыка по разным путям может считаться разными записями.

### 5.4. Назначение операций

| Операция | Результат |
|---|---|
| Добавление при показе «Вся музыка» или папки | Файлы попадают в музыку вне плейлистов |
| Добавление при выбранном плейлисте | Файлы попадают в этот плейлист |
| Открытие из Finder/Dock | Файлы попадают в очередь, начинается воспроизведение первого успешно открытого файла |
| Перетаскивание в список | Добавление в показанный раздел |
| Перетаскивание на название плейлиста | Добавление непосредственно в этот плейлист |
| Перестановка строки внутри раздела | Меняется порядок |
| Перенос между двумя плейлистами | Запись перемещается |
| Добавление из очереди в плейлист | Запись добавляется в плейлист, очередь сохраняется |
| Перенос из плейлиста в очередь | Создаётся запись в очереди; исходный плейлист сохраняется |
| Перенос из папки в плейлист | Запись копируется; папка не меняется |
| Перенос в папку | Не выполняется |
| Перетаскивание папки из Finder | Папка добавляется в раздел «Папки» |
| Перестановка в «Общем списке» | Меняется только ручной порядок общего списка, источники не меняются |

Если целевой плейлист уже содержит тот же файл, исходная запись не удаляется. При удалении назначения во время фонового импорта появляется сообщение; новый плейлист вместо удалённого не создаётся.

Просмотр раздела и фактическое воспроизведение разделены. Переключение между плейлистами само по себе не переключает текущий трек.

### 5.5. Обмен плейлистами

Выберите «Файл → Импортировать плейлист…» или перетащите M3U, M3U8 или PLS из Finder. Каждый файл создаёт отдельный плейлист с именем исходного файла. Импорт сохраняет порядок записей и оставляет первое вхождение одного файла. Названия из EXTINF и Title используются при наличии, а длительность определяется по аудиофайлу. Недоступные записи пропускаются. Сетевые адреса и потоковые списки HLS отмечаются как неподдерживаемые.

Для экспорта выберите сохранённый плейлист, затем «Файл → Экспортировать плейлист…». В диалоге сохранения выберите формат и тип путей. Относительные пути считаются от папки сохраняемого списка. Чтобы перенести список, скопируйте его и музыку, сохранив их взаимное расположение. При экспорте записываются ссылки и сведения о треках.

Параметры по умолчанию задаются в «Настройки → Плейлисты». M3U8 читается и записывается в UTF-8. Для старых M3U и PLS приложение сначала пробует Unicode, затем выбранную кодировку. Если кодировка экспорта не вмещает все символы, сохранение отклоняется с сообщением. Размер файла плейлиста ограничен 8 МиБ.

### 5.6. Теги, обложки, оценки и история

В контекстном меню трека выберите «Сведения о треке…» или «Оценка». Для пакетной правки нажмите правой кнопкой на сохранённый плейлист и выберите «Изменить теги плейлиста…». Можно снять выделение с отдельных файлов. Отметьте только поля, которые хотите записать. Пустое отмеченное поле удаляет тег. Запись заменяет файл после подготовки и проверки копии на том же томе. При остановке пакетной операции обработка прерывается между файлами, а уже сохранённые правки остаются в силе.

В редакторе можно посмотреть встроенную обложку, добавить или заменить лицевую обложку JPEG/PNG до 12 МиБ либо удалить встроенные изображения. Для новых импортов название берётся из тега, когда он доступен. Название из импортированного плейлиста имеет приоритет при добавлении из этого списка.

Оценки и статистика хранятся локально в `listening.json` рядом с библиотекой. В «Настройки → История» можно включить или отключить запись, задать порог прослушивания, срок хранения и очистить историю с подтверждением. Для коротких треков порог ограничен половиной длительности. Паузы и перемотка сами по себе время не добавляют. Последние 50 событий доступны в окне настроек. Срок хранения применяется к событиям. Накопленный счётчик и дата последнего прослушивания сохраняются до явной очистки. Очистка оставляет оценки.

### 5.7. Поиск и умные списки

Введите текст над списком треков и выберите область поиска. «Текущий раздел» ограничивает выдачу открытым плейлистом, папкой или умным списком. «Вся музыка» ищет по всей медиатеке. Поиск игнорирует регистр и диакритические знаки. Название, исполнитель, альбом, жанр, имя файла и путь доступны как поля поиска в настройках.

Кнопка «Фильтры» открывает редактор условий и сортировки. Можно сопоставлять текст, числа и даты, требовать совпадения всех либо любого условия. Длительность задаётся в секундах, относительные даты в днях. Записи из старой библиотеки без даты добавления появляются только в условиях, которые не требуют известной даты.

В разделе «Умные списки» нажмите «+». Список пересчитывается после изменения библиотеки, тегов, оценок и истории. Шаблоны и управление списками доступны в «Настройки → Поиск треков». Лимит 0 означает выдачу без ограничения. Когда вы запускаете трек из результатов или умного списка, плеер использует показанный порядок. Дальнейшее изменение запроса не перестраивает эту очередь.

## 6. Открытие и перетаскивание файлов

### 6.1. Внешние файлы

Поддерживаются локальные MP3 и FLAC. Обычный путь:

```text
Finder / файловый диалог → URL → проверка формата → декодер → очередь или плейлист
```

Перетаскивание работает через `NSItemProvider`. Внешние адреса загружаются как `public.file-url`. Порядок результатов сохраняется, даже если отдельные providers завершили загрузку в разное время.

Одновременно выполняется один импорт. Пока он идёт, справа внизу видны ход работы («Чтение файлов: 12 из 40», «Папка «Музыка»: поиск…») и кнопка «Отмена». Отмена сразу возвращает управление и не меняет библиотеку: файлы, прочитанные до отмены, не добавляются. Повторные добавления во время импорта отклоняются с сообщением.

Открытие файлов через Finder/Dock зарегистрировано в `Info.plist`. Ранг обработчика `Alternate` не назначает VibeWave проигрывателем по умолчанию автоматически.

### 6.2. Внутренние переносы

Для строки внутри приложения используется собственный тип `local.vibewave.track`. Payload содержит идентификатор исходного раздела и трека.

Тип проверяется точным совпадением в `registeredTypeIdentifiers`. Одного широкого запроса SwiftUI по совместимости типа недостаточно: ранее он приводил к направлению обычного MP3/FLAC в обработчик внутренних JSON-данных.

Строка перетаскивается мышью целиком. Чтобы поставить трек перед другим, отпустите его на нужной строке: линия показывает место вставки. Чтобы переместить в конец, отпустите в нижней свободной области списка. Строка намеренно сделана не кнопкой: кнопка на macOS перехватывает нажатие, и перетаскивание не начинается. Перестановка не прерывает текущее аудио и сразу меняет следующий трек.

## 7. Оформление и окно

### 7.1. Палитры

| Элемент | Оформление |
|---|---|
| Окно и панели | Серые панели, объёмные рамки, тёмно-синий заголовок |
| Плейлист | Белый список, чёрный текст, тёмно-синее выделение играющего трека |
| Табло | Белое вдавленное поле, чёрные цифры, индикатор уровня из синих блоков |

Оформление одно (Windows 95): квадратные элементы, объёмные грани, эффект нажатия, вдавленные поля и прямоугольные бегунки. Выбора тем нет. Видимость библиотеки и режим табло (прошедшее/оставшееся время) сохраняются через `AppStorage`.

### 7.2. Собственное окно

Приложение использует borderless-окно AppKit. Стандартной полосы с красной, жёлтой и зелёной кнопками нет. Вместо неё работает собственный заголовок с настоящими `NSButton`.

- Окно узкое и вертикальное: при закрытой библиотеке ширина подстраивается к 440 точкам, при открытой — к 620. Высота при этом не меньше 640 точек и не больше доступной области экрана. Дальше размер меняет пользователь.
- Минимальный размер содержимого — 440 × 460 точек, с открытой библиотекой — 600 × 460: нижний ряд кнопок помещается на обоих языках.
- Окно может стать key/main, поэтому поддерживается ввод с клавиатуры.
- Размер и положение сохраняются механизмом frame autosave с именем `VibeWaveMainWindow`.
- Если восстановленное окно не пересекает доступные экраны, оно центрируется.
- Разворачивание использует доступную область текущего экрана, а не фиксированное разрешение.
- Повторное нажатие значка Dock показывает закрытое или свёрнутое окно.

Файловый диалог, системное меню приложения и контекстные меню остаются нативными macOS.

### 7.3. Эквалайзер

Эквалайзер открывается кнопкой **EQ** у правого края ряда кнопок управления (⏮ ▶ ❚❚ ■ ⏭). Надпись EQ синяя, когда эквалайзер включён.

- 10 полос: 32, 64, 125, 250, 500 Гц, 1, 2, 4, 8, 16 кГц; каждая от −12 до +12 дБ с шагом 1 дБ.
- **Пред.** (предусиление) поднимает или опускает общий уровень, чтобы сильный подъём полос не перегружал звук.
- **Вкл** включает и выключает эквалайзер, не теряя настроек. Перемещение любого ползунка включает его автоматически.
- **Пресеты ▾**: «Ровно», «Рок», «Поп», «Джаз», «Классика», «Танцевальная», «Больше басов», «Больше высоких», «Вокал». Если значения изменены вручную, в меню отмечено «Свои настройки».
- **Сброс** возвращает все полосы и предусиление к 0 дБ.
- Двойной щелчок по ползунку возвращает его к 0 дБ; стрелки клавиатуры меняют значение на 1 дБ.
- Изменения слышны сразу, без перезапуска трека, и сохраняются между запусками.

### 7.4. Язык интерфейса

Интерфейс переведён на русский и английский: окно, меню приложения, подсказки, контекстные меню, диалоги, ход импорта и сообщения об ошибках.

- По умолчанию («Как в системе») берётся первый русский или английский язык из списка языков macOS («Системные настройки» → «Основные» → «Язык и регион»). Если в списке нет ни того, ни другого, выбирается английский.
- Кнопка **RU ▾ / EN ▾** в нижнем ряду открывает меню: «Как в системе (…)», «Русский», «English». Переключение происходит сразу, без перезапуска; выбор сохраняется.
- В режиме «Как в системе» смена языка macOS применяется к работающему приложению.
- Системные окна — выбор файлов и «О программе» — следуют языку macOS.
- Названия плейлистов, папок и треков не переводятся.

### 8.2. Сохранение и миграция

Плейлисты, папки и ручной порядок записываются автоматически после изменения. Запись выполняется атомарно, чтобы не оставлять частично записанный JSON. Прежний формат (массив плейлистов) читается автоматически и при следующем сохранении записывается в новом формате.

Если новой библиотеки ещё нет, приложение пробует прочитать прежнюю библиотеку «Тихо». Существующие плейлисты переносятся, исходный файл не изменяется. Если библиотека повреждена, приложение сообщает об ошибке и блокирует её молчаливую перезапись.

Ссылки на файлы могут сопровождаться security-scoped закладками. Если механизм недоступен, для локальной сборки достаточно обычного URL. Это не переносит и не копирует музыку.

### 8.3. Резервная копия

Для сохранения пользовательской коллекции:

1. Дождитесь окончания импорта.
2. Завершите приложение.
3. Скопируйте `library.json` в отдельную папку с датой.
4. Отдельно сохраните сами аудиофайлы: JSON содержит ссылки, а не звук.

Перед восстановлением сначала сохраните текущий `library.json`, даже если он повреждён. Возвращайте резервную копию при закрытом приложении.

Для резервирования разработки сохраняйте Git-репозиторий с ресурсами. Git сохраняет историю изменений. Приватный remote содержит опубликованные исходники; он не заменяет резервирование пользовательской библиотеки и музыки.

## 10. Архитектура и потоки данных

### 10.1. Слои

| Слой | Компоненты | Ответственность |
|---|---|---|
| Ядро | `VibeWaveCore` | Модели, библиотека, поиск файлов в папке, ручной порядок, форматирование |
| Состояние приложения | `PlayerModel` и его расширения | Библиотека, импорт, выбор раздела, очередь воспроизведения, сохранение |
| Фоновая работа | `MediaScanner`, `ImportJob` | Параллельное чтение файлов и папок, прогресс, отмена |
| Аудио | `AudioEngine`, `EqualizerSettings` | AVAudioEngine: плеер, эквалайзер, баланс, громкость, перемотка, уровни каналов |
| Интерфейс | `ContentView`, `ClassicPlayer`, `TrackTable`, `TrackRow`, `Theme`, `RetroControls` | Представление и пользовательские действия |
| Локализация | `Strings`, `AppLanguage` (ядро), `LanguageSettings` | Строки RU/EN, выбор языка по системе, переключение |
| Платформа | `VibeWaveApp`, `RetroWindow` | NSApplication, окно, меню, Dock, файловые события |
| Сборка и контроль | `scripts`, `Checks`, `Tests`, `.github` | Упаковка и проверки |

Ядро не зависит от SwiftUI, AppKit и аудиодекодера. Интерфейс обращается к модели, а не записывает JSON самостоятельно. Подробное устройство описано в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

### 10.2. Жизненный цикл

```text
VibeWaveApp.main
  → NSApplication
  → VibeWaveAppDelegate
  → один PlayerModel
  → один RetroWindowController
  → NSHostingView(ContentView)
```

Делегат устанавливает иконку, создаёт меню и показывает окно. Он удерживает контроллер окна, чтобы закрытое окно можно было показать повторно. При завершении приложения аудиопроигрыватель останавливается.

### 10.3. Состояние модели

`PlayerModel` помечен `@MainActor` и разделён на файлы: состояние (`PlayerModel.swift`), библиотека (`+Library`), импорт (`+Import`), воспроизведение (`+Playback`).

- `playlists`, `folders`, `libraryOrder` — сохраняемая библиотека.
- `openTracks` — музыка вне плейлистов, только в памяти.
- `selectedID` — выбранный плейлист или папка; `nil` означает «Вся музыка».
- `groupByPlaylists` — вид «По плейлистам» вместо «Общего списка».
- `visibleTracks`, `libraryEntries`, `librarySections` — производные списки для интерфейса.
- `current`, `playing`, `position`, `duration`, `volume`, `balance` — состояние проигрывания.
- `queue`, `playbackSource`, `librarySectionStart` — источник последовательного воспроизведения.
- `importing`, `importProgress`, `error` — длительная операция, её ход и пользовательское сообщение.

Назначение импорта фиксируется до фоновой работы. Переключение раздела во время импорта не направляет файлы в другой плейлист.

### 10.4. Потоки

Всё наблюдаемое состояние меняется только на главном потоке; это проверяет компилятор через `@MainActor`. Поиск файлов и их проверка декодером выполняются в фоне в `MediaScanner`: файлы открываются параллельно (`DispatchQueue.concurrentPerform`), порядок результата совпадает с исходным. Отчёты о прогрессе передаются на главный поток не чаще 10 раз в секунду. Результат применяется, только если задача не отменена и не заменена новой.

Загрузка нескольких providers синхронизируется через `DispatchGroup`, а доступ к результатам защищается `NSLock`. Завершение воспроизведения приходит из потока звука и переносится на главный поток; завершения уже отменённого расписания (стоп, перемотка, смена трека) игнорируются. Уровни каналов собираются в потоке звука и читаются под блокировкой.

При паузе периодический таймер позиции отключается; во время проигрывания позиция обновляется каждые 0,25 секунды.

## 11. Модели и формат библиотеки

### 11.1. Типы

| Тип | Основные поля |
|---|---|
| `Track` | `id: UUID`, `url: URL`, `bookmark: Data?`, `title: String`, `duration: TimeInterval` |
| `Playlist` | `id: UUID`, `name: String`, `tracks: [Track]` |
| `MusicFolder` | `id: UUID`, `url: URL`, `bookmark: Data?`, `name: String`, `tracks: [Track]` |
| `LibrarySnapshot` | `playlists`, `folders`, `order: [UUID]` |
| `TrackDragPayload` | `playlistID: UUID?` (источник: плейлист, папка или `nil`), `trackID: UUID` |
| `LibraryStore` | URL файла библиотеки; `loadSnapshot()`, `save(_:)`; `load()` для старого кода |

Название трека берётся из имени файла без расширения. Длительность — из декодера. Метаданные исполнителя и альбома в текущем интерфейсе не извлекаются.

### 11.2. JSON

Верхний уровень — объект `LibrarySnapshot`. Пример ниже иллюстративный, не содержит пользовательских данных:

```json
{
  "playlists": [
    {
      "id": "11111111-1111-4111-8111-111111111111",
      "name": "Вечер",
      "tracks": [
        {
          "id": "22222222-2222-4222-8222-222222222222",
          "url": "file:///Users/example/Music/Track.flac",
          "title": "Track",
          "duration": 258
        }
      ]
    }
  ],
  "folders": [
    {
      "id": "33333333-3333-4333-8333-333333333333",
      "url": "file:///Users/example/Music/Albums/",
      "name": "Albums",
      "tracks": []
    }
  ],
  "order": ["22222222-2222-4222-8222-222222222222"]
}
```

`folders` и `order` необязательны: без них библиотека читается с пустыми значениями. Прежний формат — массив плейлистов на верхнем уровне — тоже читается. `order` содержит только ID сохраняемых треков: музыка вне плейлистов в нём не записывается.

При наличии `bookmark` Codable записывает данные как Base64-строку. Версия приложения не является отдельным полем схемы JSON; при будущем изменении схемы потребуется явная совместимая миграция.

## 12. Аудиовоспроизведение и обработка ошибок

Текущим треком управляет `AudioEngine` на основе `AVAudioEngine`: файл (`AVAudioFile`) → `AVAudioPlayerNode` → эквалайзер `AVAudioUnitEQ` → микшер баланса и громкости → выход. Движок открывает security-scoped доступ к файлу и считает уровни каналов для индикатора. При смене трека прежнее воспроизведение останавливается, а доступ закрывается. При смене аудиовыхода (наушники, AirPods) воспроизведение продолжается с той же позиции. Устаревшая закладка пересоздаётся и обновляется во всех источниках, где встречается трек.

Ошибка декодирования, недоступный файл или невозможность воспроизведения превращаются в сообщение пользователю. При частично успешном импорте исправные файлы добавляются, а проблемные перечисляются с причинами отказа (первые десять имён и число остальных).

Во время импорта имя с расширением MP3/FLAC не считается достаточным доказательством исправности: файл открывает тот же декодер (`AVAudioFile`), что потом его играет, и по нему же считается длительность. URL из сети не принимаются как локальная музыка.

Перемотка ограничивается диапазоном от нуля до длительности. После окончания трека модель применяет текущий режим повтора и порядок очереди. Если после смены аудиовыхода продолжить не удалось, воспроизведение останавливается с сообщением «Аудиоустройство недоступно».

## 12а. Автообновление

Начиная с 2.0 VibeWave обновляется сам. Настроек и отдельного окна нет; версии до 2.0 нужно один раз обновить вручную.

### Как это выглядит

1. При каждом запуске, через пару секунд после появления окна, VibeWave в фоне читает `update.json` из последнего релиза: `https://github.com/Slipcast-dev/VibeWave/releases/latest/download/update.json`. Ошибки сети не показываются.
2. Если версия в `update.json` новее установленной, а macOS не старше требуемой, появляется вопрос «Доступно обновление VibeWave» с кнопками **«Обновить»** и **«Позже»**. «Позже» — вопрос повторится при следующем запуске.
3. После «Обновить» ZIP скачивается в фоне, пока работает плеер.
4. Если ничего не играет, VibeWave закрывается, отдельный процесс заменяет приложение, и новая версия открывается сама. Если играет музыка, замена ждёт остановки воспроизведения (кнопка «Стоп» или конец очереди). Если программу закрыть раньше, обновление ставится при выходе без повторного открытия.

### Проверки перед установкой

| Проверка | Что защищает |
|---|---|
| SHA-256 архива совпадает с `update.json` | Повреждённая загрузка |
| Подпись Ed25519 архива открытым ключом из `Info.plist` (`VWUpdatePublicKey`) | Подменённый архив или `update.json`, даже при доступе к релизам на GitHub |
| `CFBundleIdentifier` внутри — `local.vibewave.player` | Чужое приложение в архиве |
| Версия внутри совпадает с обещанной и новее установленной | Откат на старую версию |
| `codesign --verify --strict` | Повреждённая сборка |
| Только HTTPS | Подмена по дороге |

При ошибке проверки обновление не ставится, а пользователь получает сообщение «Обновление … не прошло проверку».

### Замена приложения

Отдельный процесс `/bin/sh` ждёт завершения VibeWave, переименовывает прежнее приложение в `VibeWave.app.vibewave-previous`, ставит новое на его место и удаляет прежнее. Если поставить новое не удалось, прежнее возвращается. Атрибут карантина снимается. Если у пользователя нет прав на запись в папку приложения, macOS один раз попросит пароль администратора. PKG после установки передаёт приложение пользователю, вошедшему в систему, поэтому обновление обычно проходит без пароля.

Обновление отключено, если приложение запущено не из `.app`, из образа диска или из карантинной копии (App Translocation), либо лежит на томе только для чтения.

### Ключ подписи обновлений

Закрытый ключ Ed25519 лежит у разработчика в `~/.config/vibewave/update-signing-key` (права 600) и **никогда** не попадает в репозиторий. Открытый ключ записан в `Resources/Info.plist`. Без закрытого ключа нельзя выпустить обновление, которое примут установленные копии, поэтому его резервную копию нужно хранить отдельно и безопасно. При утере ключа придётся выпустить версию с новым открытым ключом и попросить пользователей поставить её вручную.

`scripts/tools/UpdateSigner.swift` (собирается `package-release.sh`): `generate` создаёт ключ, `public` выводит открытый ключ, `manifest` подписывает ZIP и выводит `update.json`.

## 13. Иконка и упаковка приложения

Исходная иконка — `Assets/AppIcon.png`: фиолетовая волна на тёмной скруглённой плитке с прозрачностью снаружи.

Скрипт создаёт размеры 16, 32, 128, 256 и 512 пикселей и варианты `@2x`, затем собирает `VibeWaveIcon.icns` через `iconutil`. Ресурс включается в `Contents/Resources/`, а `CFBundleIconFile` указывает на его имя.

Приложение также явно устанавливает изображение через `NSApplication.applicationIconImage` и именованную иконку AppKit. Это устраняет зависимость работающего Dock-значка от прежнего стандартного изображения в кеше.

`Resources/Info.plist` — шаблон. `VERSION` — единственный источник номера релиза. В шаблоне служебные номера заменяются скриптом при упаковке.

## 14. Автоматические и ручные проверки

### 14.1. Команды

Из каталога проекта:

```sh
zsh scripts/build-app.sh
zsh scripts/check.sh
```

`check.sh` можно запускать и без собранного `.app`: тогда пропускается только проверка иконки.

При полном Xcode:

```sh
swift test
```

Проверка подписи:

```sh
codesign --verify --strict --verbose=2 dist/VibeWave.app
```

### 14.2. Покрытие

Регрессионный сценарий компилирует реальные исходники и проверяет:

- перенос прежней библиотеки без изменения исходного файла;
- сохранение и восстановление плейлистов;
- отсутствие автоматически создаваемых плейлистов;
- независимость временной очереди;
- импорт настоящих MP3/FLAC через providers;
- точное определение внутреннего типа переноса;
- перестановку, переносы и защиту дублей;
- явное добавление в плейлист и открытие из Finder;
- папки: сканирование, повторное добавление, недоступная папка не очищается;
- в папку попадают только обычные видимые файлы; каталог `Album.mp3` не даёт ошибку;
- обновление папки сохраняет ID известных треков и добавляет новые;
- переключение языка меняет строки модели, ход импорта, сообщения и подсказки окна;
- воспроизведение через AVAudioEngine: длительность, перемотка, смена эквалайзера без остановки, автопереход, остановка после последнего трека, сохранение эквалайзера;
- прогресс импорта виден во время работы и скрывается после неё;
- отмена сразу снимает блокировку и не меняет библиотеку;
- «Вся музыка» без дублей, ручной порядок, вид «По плейлистам»;
- навигация следующий/предыдущий по списку и после ручного переноса;
- валидность иконки AppKit;
- отсутствие системного заголовка у окна;
- возможность окна стать key/main;
- наличие трёх подключённых кнопок;
- разворачивание и восстановление размеров.

XCTest дополнительно покрывает ядро: допустимые форматы, повреждённый JSON, исключение дублей, порядок, совместимость формата библиотеки, поиск файлов в папке (скрытые файлы, каталоги, пакеты, символические ссылки, порядок как в Finder, отмена), слияние папки без повторного чтения, выбор языка по системе, строки обоих языков, пределы и пресеты эквалайзера и форматирование времени.

GitHub Actions на `macos-15-intel` запускает `swift test`, сборку, проверку подписи и `scripts/check.sh`.

Фикстуры содержат короткую тишину. Испытания используют временную библиотеку и не меняют коллекцию пользователя.

### 14.3. Зафиксированный статус

Для версии 2.0.0 на arm64 (Swift 6.4.2, macOS SDK 27.2, полный Xcode) выполнены `swift test` (13 тестов), `scripts/check.sh` для arm64 и x86_64 (Rosetta), универсальная сборка и сборка установщиков. В CI на `macos-15-intel` `scripts/check.sh` выполняется без проверок окна (у раннера нет видеокарты). Публичная нотариализованная сборка не проверена.

Для версии 0.5.0 ранее выполнены локальная сборка, проверка подписи и регрессионный сценарий на x86_64.

### 14.4. Ручная приёмка перед выпуском

1. Запуск чистого приложения без автоматического плейлиста.
2. Добавление нескольких MP3/FLAC в очередь.
3. Создание плейлиста, явное добавление и восстановление после перезапуска.
4. Перетаскивание файлов и строк, в том числе в конец списка и на другой плейлист.
5. Добавление большой папки: виден ход работы, «Отмена» останавливает добавление, повторное «Обновить содержимое» быстро дочитывает только новые файлы.
6. Воспроизведение, пауза, стоп, переключение, перемотка, громкость и баланс на реальной музыке.
7. Удалённый, перемещённый и повреждённый файл.
8. Контраст выделений и клавиатурный фокус.
9. Перемещение окна, изменение размера, сворачивание, разворачивание и закрытие.
10. Повторное открытие окна через Dock и завершение через `⌘Q`.
11. Проверка подписанного распространяемого пакета на отдельной машине без данных разработки.

Автоматические проверки не заменяют физическую проверку жестов и поведения Dock.

## 15. Безопасность и конфиденциальность

- Единственный сетевой доступ — HTTPS-запросы к GitHub для автообновления: `update.json` при запуске и архив обновления после согласия пользователя. Никакие данные о пользователе, библиотеке или музыке не отправляются; ключей API нет.
- Обновления подписаны Ed25519; закрытый ключ хранится только у разработчика вне репозитория (см. раздел 12а).
- В библиотеку записываются пути к музыке и названия плейлистов. Это пользовательские данные: не публикуйте `library.json` без проверки содержимого.
- Исходная музыка не удаляется и не перезаписывается операциями библиотеки.
- Локальная версия работает без App Sandbox. Это фактическая конфигурация сборки, а не инструкция отключать защиту macOS.
- Для публичной сборки права доступа и entitlements необходимо проверить отдельно.
- Секреты подписи и учётные данные Developer Program нельзя хранить в исходниках, Markdown-файлах или Git.
- `.gitignore` исключает `.env`, локальные настройки, кеши и сборки.
- Перед изменением пользовательской библиотеки, очисткой исходников или миграцией сохраняется резервная копия.

## 16. Устранение неполадок

| Симптом | Проверка и действие |
|---|---|
| Файл не добавляется | Проверить локальный путь, расширение и возможность чтения; изучить причину в сообщении импорта. Проверить, выбран ли нужный раздел |
| В папке не видно файла | Скрытые файлы, файлы внутри пакетов и каталоги с расширением `.mp3`/`.flac` пропускаются намеренно. После добавления файлов на диск выбрать «Обновить содержимое» |
| Добавление папки идёт долго | Ход работы виден справа внизу; «Отмена» останавливает операцию без изменений библиотеки |
| Появляется сообщение о внутреннем треке при внешнем файле | Убедиться, что запущена актуальная сборка; проверить точное определение типа в `DropReceiver` и регрессионный путь providers |
| `Failed to retrieve app-scope key` | Закладка в локальной сборке должна оставаться необязательной; её ошибка не должна отклонять исправный аудиофайл |
| Файл переместили или удалили | Добавить его заново из актуального местоположения; не изменять JSON наугад |
| Нет звука | Проверить громкость плеера, системный выход и доступность аудиоустройства; проверить другой исправный файл |
| Очередь исчезла после завершения | Ожидаемое поведение; для постоянного хранения создать плейлист |
| Нет окна после нажатия крестика | Нажать значок приложения в Dock; закрытие окна не завершает процесс |
| Видна старая версия интерфейса | Завершить старую копию и открыть именно `dist/VibeWave.app` из текущего проекта |
| Стандартный значок вместо иконки | Проверить наличие `VibeWaveIcon.icns`, запись `CFBundleIconFile`, подпись bundle и запуск текущей сборки |
| SwiftPM сообщает об отсутствующем PlatformPath | Запускать `scripts/build-app.sh`; он использует прямую сборку. Для XCTest установить полный Xcode |
| Ошибка пути PCH/module cache | Использовать новый кеш по стабильному пути; не копировать кеш между каталогами |
| Иконка не упаковывается | Проверить исходный PNG, размеры iconset и ошибку `iconutil`; не распространять частично собранный bundle |
| Библиотека не читается | Сохранить проблемный JSON отдельно, проверить резервную копию. Приложение намеренно не перезаписывает повреждённые данные |

Не отключайте SIP, Gatekeeper или проверку подписи для устранения этих ошибок.

## 18. Подготовка релиза и откат

### 18.1. Локальный релиз

`scripts/package-release.sh` превращает проверенный `dist/VibeWave.app` в установщики в каталоге `.release/v<версия>-<платформа>/` (платформа `universal` для arm64 + x86_64):

| Файл | Назначение |
|---|---|
| `VibeWave-<версия>-macos-universal.dmg` | Образ диска с приложением и ссылкой на «Программы» для установки перетаскиванием |
| `VibeWave-<версия>-macos-universal.pkg` | Мастер установки: ставит VibeWave в `/Applications`, требует macOS 13+, не переносит установку в другую найденную копию |
| `VibeWave-<версия>-macos-universal.zip` | Архив приложения |
| `SHA256SUMS.txt` | Контрольные суммы трёх файлов |

Существующие файлы не перезаписываются. Подпись остаётся ad hoc: установщики не подписаны Developer ID и не нотариализованы, поэтому на другом Mac Gatekeeper попросит подтверждение.

1. Проверить изменения и актуальность `VERSION`.
2. Обновить журнал изменений и документацию.
3. Собрать приложение и запустить проверки.
4. Выполнить ручную приёмку.
5. Проверить подпись.
6. Сохранить отдельно нужный предыдущий bundle и пользовательскую библиотеку.
7. Передать проверенную локальную сборку владельцу проекта.

Изменения только Markdown не требуют повышения версии исполняемого приложения.

### 18.2. Публичное распространение — отдельный этап

Для прямого распространения вне Mac App Store следует подготовить Developer ID-подпись, Hardened Runtime, проверенные разрешения и отправку на нотариализацию. Apple предоставляет `notarytool` и `stapler`; ad hoc подпись текущего скрипта не заменяет этот процесс. Требования и порядок подтверждаются по [официальной документации Apple](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution).

План публичного выпуска:

1. Уточнить поддерживаемые архитектуры и канал доставки.
2. Подготовить отдельную конфигурацию подписи и упаковки; не помещать секреты в Git.
3. Проверить сборки на заявленных архитектурах.
4. Настроить Developer ID, Hardened Runtime и необходимые entitlements.
5. Подписать исполняемые компоненты и сформировать распространяемый пакет.
6. Отправить пакет на нотариализацию, проверить результат и журнал.
7. Прикрепить ticket к поддерживаемому артефакту и повторно проверить его.
8. Проверить чистую установку/открытие на другом Mac.
9. Подготовить номер версии, release notes, контрольную сумму и план отката.
10. Публиковать только в явно согласованный канал.

Это план последующего этапа, а не описание уже выполненной публикации. Текущий `build-app.sh` потребуется расширить или дополнить отдельным release-сценарием. Простая повторная локальная сборка снова создаст ad hoc bundle.

### 18.3. Откат

До обновления сохранить прежний проверенный `.app` вне `dist/`, поскольку каталог сборки заменяется. При проблеме завершить текущую версию и открыть сохранённую. Исходники восстанавливать через отдельную ветку или checkout нужного коммита, сохранив незакоммиченные изменения. Не использовать `git reset --hard` как обычный способ отката.

Если менялась схема пользовательских данных, откат приложения допустим только с совместимой библиотекой либо её предварительно сохранённой копией.

## 19. Ограничения и история разработки

### 19.1. Текущие ограничения

- Поддерживаются только локальные MP3/FLAC; сетевые потоки не реализованы. Папки не отслеживаются автоматически: новые файлы появляются после «Обновить содержимое».
- Редактор MP3 поддерживает обычные ID3v2.3/v2.4 без глобальных флагов. ID3v1 читается при отсутствии ID3v2. Для FLAC поддерживаются Vorbis Comment и PICTURE в стандартном контейнере fLaC.
- Бесшовные переходы и отдельный режим bit-perfect пока не реализованы.
- Очередь, позиция и громкость не сохраняются как состояние сеанса между завершениями приложения.
- На первом уровне JSON нет отдельной версии схемы.
- Публичная подпись Developer ID, нотариализация и автоматическая доставка обновлений не реализованы. Универсальная сборка и установщики DMG/PKG есть, но подписаны ad hoc.
- Потребление CPU/RAM, предельный размер медиатеки и работа на всех поддерживаемых компьютерах не имеют опубликованных измерений.

## Оформление GitHub

Главная страница есть на двух языках: `README.md` (русский) и `README.en.md` (английский), со ссылками друг на друга в первой строке. Каждая содержит SVG-баннеры (заголовок и сведения о релизе) на своём языке, ряд значков и скриншоты окна и эквалайзера на тестовых данных.

Значки лежат в `docs/assets/badges/` и рисуются скриптом `scripts/update-badges.sh` в стиле Windows 95: версия (из `VERSION`), macOS 13+, Apple Silicon + Intel, языки RU/EN, Swift 5.8+, звёзды и скачивания. Звёзды и скачивания скрипт берёт из GitHub API через `gh` (скачивания — сумма загрузок файлов всех релизов без `SHA256SUMS.txt` и `update.json`): числа фиксируются при запуске скрипта, обычно при релизе. Готовые счётчики вроде shields.io не используются: они считают и `update.json`, который каждая копия читает при запуске. Без доступа к GitHub прежние значки звёзд и скачиваний не меняются.

Репозиторий публичный с версии 2.0: без этого установленные копии не могли бы получать обновления из релизов.

В `.github/` находятся CODEOWNERS, issue forms, шаблон pull request, Dependabot для Actions и workflow на `macos-15-intel`: тесты ядра, универсальная сборка, проверка подписи и обоих срезов, регрессионные проверки `scripts/check.sh` и сборка установщиков без публикации. Автоматическая публикация и доступ к сертификатам в workflow не настраиваются. Состояние CI следует проверять по фактическому запуску, а не по статическому баннеру.

Политики участия, безопасности и поведения находятся в `CONTRIBUTING.md`, `SECURITY.md` и `CODE_OF_CONDUCT.md`. Открытая лицензия не выбрана: код доступен для чтения, но права на использование и изменение не предоставлены. Защита ветки `main` не заявляется включённой.


### Повторяемая упаковка GitHub-релиза

После сборки и проверок выполните `zsh scripts/package-release.sh`. Скрипт сверяет версию `.app` с `VERSION`, проверяет подпись и архитектуры, затем сохраняет DMG, PKG, ZIP, `SHA256SUMS.txt` и подписанный `update.json` в `.release/v<версия>-<платформа>/`. Без ключа подписи (например, в CI) `update.json` не создаётся; `VIBEWAVE_REQUIRE_UPDATE_SIGNATURE=1` превращает это в ошибку. Заметки к обновлению — `VIBEWAVE_UPDATE_NOTES_RU` и `VIBEWAVE_UPDATE_NOTES_EN`. `update.json` обязательно прикладывается к каждому релизу, иначе автообновление его не увидит. Каталог не включается в исходники. Если любой из этих файлов уже существует, скрипт требует отдельный выходной каталог и ничего не перезаписывает. Сама команда ничего не публикует.
