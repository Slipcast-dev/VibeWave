# Участие в разработке

VibeWave — минималистичный macOS-плеер; репозиторий публичный, открытая лицензия не выбрана. Перед работой прочитайте [полную документацию](DOCUMENTATION.md) и существующие issues.

## Изменения

1. Создайте отдельную ветку от актуальной `main`.
2. Сформулируйте конкретную проблему и сохраните небольшой объём изменения.
3. Не добавляйте аккаунты, облако и необязательные экраны без согласованной задачи.
4. Не смешивайте временную очередь и ручные плейлисты. Не удаляйте пользовательскую музыку.
5. Комментируйте сложную логику на русском языке; придерживайтесь соглашений Swift.

## Проверка

```sh
zsh scripts/build-app.sh
zsh scripts/check.sh
# При полном Xcode:
swift test
git diff --check
```

CI проверяет сборку и XCTest на macOS Intel. Регрессионный сценарий с аудио и окнами запускайте локально. После изменения интерфейса проверьте все темы, работу кнопок, перетаскивание и ползунки. Не отмечайте непроверенный сценарий выполненным.

## Pull request

Опишите причину, результат и выполненные проверки. Добавьте обезличенный снимок при изменении интерфейса. Обновите `CHANGELOG.md` и документацию, если меняется поведение. Для коммитов рекомендуются `feat:`, `fix:`, `docs:`, `test:` и `chore:`.

Не добавляйте `.build/`, `dist/`, личную библиотеку, пути к приватной музыке, токены и сертификаты. Перед изменением схемы данных подготовьте совместимость и откат.

## Релиз

Версия хранится в `VERSION`. Изменения только документации не требуют нового номера приложения. Готовые бинарные архивы размещаются в GitHub Releases, а не в исходниках. Подпись Developer ID и нотариализация — отдельный этап; локальная ad hoc подпись не заменяет его.

Открытая лицензия для проекта не выбрана. Вопросы о распространении согласуются с владельцем репозитория.
