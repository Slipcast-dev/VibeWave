# Проверка VibeWave

## Автоматические проверки

```sh
zsh scripts/build-app.sh
zsh scripts/check.sh
```

Регрессионный сценарий работает с Command Line Tools без XCTest. Он компилирует рабочие исходники и проверяет:

- миграцию прежней библиотеки и сохранение пользовательских плейлистов;
- отсутствие автоматически создаваемых плейлистов;
- импорт настоящих коротких MP3/FLAC через файловые providers;
- разделение внешних файлов и внутренних drag payload;
- независимость временной очереди и явное добавление в плейлист;
- перестановку вверх, вниз и в конец, переносы и защиту дублей;
- сохранение порядка после повторного чтения JSON;
- открытие из Finder при выбранном плейлисте;
- чтение упакованной иконки AppKit;
- отсутствие системной полосы у borderless-окна, возможность key/main;
- наличие трёх подключённых кнопок заголовка и разворачивание/восстановление окна.

Проверки используют отдельный временный каталог. Фикстуры в `Checks/Fixtures` содержат короткую тишину, созданную для проекта.

При полном Xcode доступен дополнительный набор ядра:

```sh
swift test
```

Он проверяет JSON, повреждённые данные, форматы, дубликаты, перестановку и подписи времени. Если установлен только Command Line Tools и отсутствует PlatformPath, используйте `scripts/check.sh`.

## Ручная приёмка

1. Запустить `dist/VibeWave.app`. Убедиться, что нет стандартной верхней полосы macOS и повторяющейся подписи очереди.
2. Передвинуть окно за заголовок; дважды щёлкнуть по нему для разворачивания и восстановления.
3. Проверить сворачивание, восстановление через Dock и закрытие крестиком. После закрытия нажать значок в Dock — окно должно открыться снова.
4. Изменить размер окна за край; перезапустить приложение и проверить сохранение положения.
5. Выбрать каждую из трёх тем. Проверить контраст текста, эффект нажатия кнопок и ползунки.
6. Добавить MP3/FLAC в очередь. Плейлист не должен создаться.
7. Создать плейлист кнопкой `+`, добавить туда музыку, переставить треки и проверить результат после перезапуска.
8. Проверить паузу, переключение треков, перемотку, громкость и обработку недоступного файла.
9. Проверить `⌘O`, `⌘W`, `⌘M`, `⌘Q` и редактирование названий с копированием/вставкой.

Автоматические проверки действий окна не заменяют ручную проверку физического перетаскивания и управления через Dock. Отрисовку интерфейса можно дополнительно проверить на отдельной тестовой модели без пользовательской медиатеки.


## Проверено для 0.5.0 — 8 ноября 2026

Сборка Swift 5.8.1 / macOS SDK 13.3 для x86_64, упаковка и проверка подписи прошли. Регрессионный сценарий прошёл, включая отдельное borderless-окно, три подключённые кнопки заголовка и разворачивание/восстановление. Полный XCTest в текущем окружении с Command Line Tools не запускался; он требует полного Xcode.


## GitHub Actions и упаковка релиза

`.github/workflows/ci.yml` запускает XCTest ядра, сборку `.app` и проверку подписи на `macos-15-intel`. Проверка звука, окон и реальных жестов остаётся отдельной локальной приёмкой. Workflow имеет только `contents: read`; сертификаты и секреты публикации в него не добавляются.

Проверенную сборку можно упаковать командой `zsh scripts/package-release.sh`. Она создаёт ZIP с названием версии и фактической архитектурой, а также `SHA256SUMS.txt` в исключённом из Git каталоге `.release/`. Упаковка не выполняет загрузку на GitHub и не делает локальную подпись Developer ID-подписью.


## Проверки 0.6.0

Добавлены проверки явного источника действий при выбранном плейлисте, ручной перестановки, уникальности случайной последовательности, сохранения истории следующего/предыдущего и возврата к порядку списка после ручного переноса. Визуальный экспорт с тестовыми треками показывает плейлист и музыку вне него одновременно.

Ручная приёмка: перетянуть правую границу каждого заголовка, перезапустить и проверить размеры; сбросить двойным щелчком; переставить трек за полоски перед другой строкой и в конец; проверить следующий трек. Выбрать случайный режим, затем вручную переставить трек — режим должен стать «По списку». При выбранном плейлисте проверить независимость списка «Вне плейлистов».
