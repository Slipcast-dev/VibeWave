# Проверка VibeWave

## Автоматические проверки

```sh
zsh scripts/build-app.sh
zsh scripts/check.sh
```

Регрессионный сценарий работает с Command Line Tools без XCTest. Он компилирует все исходники приложения (кроме точки входа `VibeWaveApp.swift`) по маске и проверяет:

- миграцию прежней библиотеки и сохранение пользовательских плейлистов;
- отсутствие автоматически создаваемых плейлистов;
- импорт настоящих коротких MP3/FLAC через файловые providers;
- разделение внешних файлов и внутренних drag payload;
- независимость временной очереди и явное добавление в плейлист;
- перестановку вверх, вниз и в конец, переносы и защиту дублей;
- сохранение порядка после повторного чтения JSON;
- открытие из Finder при выбранном плейлисте;
- чтение упакованной иконки AppKit;
- отсутствие системной полосы у borderless-окна, возможность key/main;
- наличие трёх подключённых кнопок заголовка и разворачивание/восстановление окна;
- папки: сканирование, повторное добавление, недоступная папка не очищается;
- в папку попадают только обычные видимые файлы, каталог `Album.mp3` не даёт ошибку;
- обновление папки сохраняет ID известных треков и дочитывает только новые;
- ход импорта виден во время работы и скрывается после неё;
- отмена сразу снимает блокировку и не меняет библиотеку (для папок и для файлов);
- воспроизведение через AVAudioEngine с эквалайзером: длительность FLAC/MP3, перемотка, смена настроек эквалайзера без остановки трека, автопереход, остановка после последнего трека, сохранение настроек;
- переключение языка: строки модели, раздел «Вне плейлистов», ход импорта, сообщения об ошибках и подсказки кнопок окна сразу меняются между русским и английским.

Проверки устанавливают русский язык на время работы, поэтому не зависят от языка системы.

Без собранного `dist/VibeWave.app` пропускается только проверка иконки. Проверки используют отдельный временный каталог. Фикстуры в `Checks/Fixtures` содержат короткую тишину, созданную для проекта.

При полном Xcode доступен дополнительный набор ядра:

```sh
swift test
```

Он проверяет пределы, пресеты и чтение сохранённых настроек эквалайзера, выбор языка по списку языков системы, строки обоих языков с подстановками, JSON, повреждённые данные, форматы, дубликаты, перестановку, совместимость формата библиотеки, поиск файлов в папке (скрытые файлы, каталоги, пакеты, символические ссылки, порядок как в Finder, отмена), слияние папки без повторного чтения и подписи времени. Если установлен только Command Line Tools и отсутствует PlatformPath, используйте `scripts/check.sh`.

## Ручная приёмка

1. Запустить `dist/VibeWave.app`. Убедиться, что нет стандартной верхней полосы macOS и повторяющейся подписи очереди.
2. Передвинуть окно за заголовок; дважды щёлкнуть по нему для разворачивания и восстановления.
3. Проверить сворачивание, восстановление через Dock и закрытие крестиком. После закрытия нажать значок в Dock — окно должно открыться снова.
4. Изменить размер окна за край; перезапустить приложение и проверить сохранение положения.
5. Проверить контраст текста, эффект нажатия кнопок и ползунки громкости, баланса и позиции.
6. Добавить MP3/FLAC в очередь. Плейлист не должен создаться.
7. Создать плейлист кнопкой `+` в библиотеке, добавить туда музыку, переставить треки и проверить результат после перезапуска.
8. Добавить большую папку: справа внизу виден ход работы; «Отмена» останавливает добавление без изменений. Повторно добавить и выбрать «Обновить содержимое» — обновление должно пройти быстро.
9. Проверить паузу, переключение треков, перемотку, громкость и обработку недоступного файла.
10. Проверить пробел, `⌘O`, `⌘W`, `⌘M`, `⌘Q` и редактирование названий с копированием/вставкой.

Автоматические проверки действий окна не заменяют ручную проверку физического перетаскивания и управления через Dock. Отрисовку интерфейса можно дополнительно проверить на отдельной тестовой модели без пользовательской медиатеки.

## GitHub Actions и упаковка релиза

`.github/workflows/ci.yml` на `macos-15-intel` запускает XCTest ядра, универсальную сборку `.app`, проверку подписи и наличия срезов arm64 и x86_64, `scripts/check.sh` и сборку установщиков без публикации. Срез arm64 на Intel-раннере только собирается: запустить его там нельзя. У раннера GitHub нет видеокарты, и окно SwiftUI не может отрисоваться через Metal. Поэтому в CI задана переменная `VIBEWAVE_SKIP_WINDOW_CHECKS=1`: проверки окна (borderless, кнопки заголовка, разворачивание) пропускаются с пометкой `SKIP` и выполняются только локально. Остальные регрессионные проверки идут полностью. Проверка звука, окон и реальных жестов остаётся отдельной локальной приёмкой. Workflow имеет только `contents: read`; сертификаты и секреты публикации в него не добавляются.

Проверенную сборку можно упаковать командой `zsh scripts/package-release.sh`. Она создаёт DMG, PKG и ZIP с названием версии и платформы (`universal` для arm64 + x86_64), а также `SHA256SUMS.txt` в исключённом из Git каталоге `.release/v<версия>-<платформа>/`. Существующие файлы не перезаписываются. Упаковка не выполняет загрузку на GitHub и не делает локальную подпись Developer ID-подписью.

Выбрать случайный режим, затем вручную переставить трек — режим должен стать «По списку». При выбранном плейлисте проверить независимость списка «Вне плейлистов».

## Универсальная сборка и установщики — 9 ноября 2026

На Apple Silicon собрано универсальное приложение (`lipo`: x86_64 arm64) через SwiftPM; прямая сборка `swiftc` также проверена для обеих архитектур. `scripts/check.sh` прошёл для arm64 и для x86_64 (`VIBEWAVE_CHECK_ARCH=x86_64`, через Rosetta). DMG подключён только для чтения: внутри универсальное приложение с действительной подписью и ссылка на «Программы». PKG развёрнут через `pkgutil`: универсальное приложение, установка в `/Applications`, перемещение отключено, `hostArchitectures="arm64,x86_64"`, минимум macOS 13. Реальная установка PKG и запуск на Intel-Mac не выполнялись.

Ручная приёмка перед выпуском: установить из DMG и из PKG на Apple Silicon и на Intel, проверить запуск, звук и подтверждение Gatekeeper для ad hoc подписи.


## Локализация — 9 ноября 2026

`swift test` (9 тестов) и `scripts/check.sh` прошли для arm64 и x86_64 (Rosetta). Окно отрисовано на тестовой модели на русском и английском при минимальной ширине 440 точек: нижний ряд помещается целиком, текст не обрезается.

## Эквалайзер — 9 ноября 2026

`swift test` (10 тестов) и `scripts/check.sh` прошли для arm64 и x86_64 (Rosetta), включая воспроизведение фикстур через AVAudioEngine. Офлайн-замер цепочки на тоне: полоса 1K +12 дБ даёт +12,0 дБ на 1 кГц и +0,1 дБ на 125 Гц; выключатель — 0 дБ; предусиление −6 дБ — −6,0 дБ; баланс −1/+1 оставляет только левый/правый канал; громкость 0,5 снижает уровень вдвое. Панель отрисована на русском и английском.

Не проверено: реальное звучание на слух, смена аудиовыхода во время воспроизведения, работа AVAudioEngine на GitHub-раннере без аудиоустройства.

Ручная приёмка: EQ открывается и закрывается; пресеты слышны сразу; «Вкл» выключает эффект без потери настроек; двойной щелчок по ползунку — 0 дБ; после перезапуска настройки сохранены; при переключении на наушники звук продолжается с той же позиции.
