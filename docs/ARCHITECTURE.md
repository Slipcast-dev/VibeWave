# Архитектура VibeWave

## Технологии и границы ответственности

- **Swift 5.8+, SwiftUI:** панель плеера, список треков, библиотека, объёмные кнопки и ползунки.
- **AppKit:** жизненный цикл приложения, собственное окно без стандартной полосы macOS, системные меню, файловые диалоги, иконка и область перемещения окна.
- **AVFoundation / AVAudioPlayer:** проверка и декодирование MP3/FLAC, воспроизведение текущего трека, уровни каналов для индикатора.
- **Foundation / Codable:** JSON-библиотека, поиск файлов в папках, закладки файлов и атомарная запись.
- Сторонних пакетов и сетевого доступа у приложения нет.

### VibeWaveCore

Ядро не зависит от SwiftUI, AppKit и аудиодекодера и покрыто XCTest.

- `Track` ссылается на исходный файл: URL, необязательная security-scoped закладка, название из имени файла и длительность.
- `Playlist` — ручной плейлист: идентификатор, имя, порядок треков.
- `MusicFolder` — папка на диске со списком найденных треков. `merge(files:added:)` сохраняет ID и порядок известных файлов, убирает исчезнувшие и добавляет новые в конец; известные файлы не нужно открывать повторно.
- `LibrarySnapshot` — то, что хранится на диске: плейлисты, папки и ручной порядок раздела «Вся музыка». Отсутствующие `folders` и `order` читаются как пустые.
- `LibraryStore` читает и атомарно записывает JSON. Старый формат (массив плейлистов) читается без изменения файла.
- `ManualOrder` — ручной порядок общего списка: известные ID по порядку, новые в конце.
- `MusicFiles.collect(in:isCancelled:)` рекурсивно ищет MP3/FLAC. Берутся только обычные файлы и символические ссылки на обычные файлы; скрытые файлы, каталоги с «музыкальным» расширением и содержимое пакетов (`.app` и т. п.) пропускаются. `nil` означает недоступную папку, отмена — `CancellationError`.
- `TrackDragPayload` — содержимое внутреннего переноса: ID источника и трека.

Значимые типы ядра объявлены `Sendable`: их безопасно передавать из фоновых потоков.

### PlayerModel

Один экземпляр принадлежит делегату приложения; SwiftUI наблюдает за его `@Published`-состоянием. Класс помечен `@MainActor`: компилятор проверяет, что состояние меняется только на главном потоке. Фоновая работа вынесена в `MediaScanner`, а результаты возвращаются через `DispatchQueue.main`.

Модель разделена на расширения по файлам:

| Файл | Ответственность |
|---|---|
| `PlayerModel.swift` | Хранимое состояние, загрузка и миграция библиотеки, `save()`, выбор раздела, `libraryEntries`, `librarySections`, `tracks(in:)` |
| `PlayerModel+Library.swift` | Создание, переименование и удаление плейлистов; удаление папок и треков; `moveTrack`, `moveTrackBy`, `moveInLibrary` |
| `PlayerModel+Import.swift` | Диалоги, открытие из Finder/Dock, `receiveFiles`, `importURLs`, `addFolders`, `rescanFolder`, `cancelImport` |
| `PlayerModel+Playback.swift` | `play`, `playLibrary`, `toggle`, `seek`, `next`, `previous`, `stop`, обновление очереди и закладок |

Основные правила:

- `selectedID == nil` — раздел «Вся музыка»; иначе выбран плейлист или папка.
- `openTracks` — музыка вне плейлистов. Она живёт только в памяти и не сохраняется.
- `current`, `queue`, `playbackSource` и `librarySectionStart` описывают воспроизведение отдельно от просматриваемого раздела.
- `playbackSource` — `.container(id)` (плейлист, папка или `nil` для очереди) либо `.library` («Вся музыка» в текущем виде).
- `createPlaylist` вызывается только явной командой пользователя.
- Изменения состава и порядка вызывают `refreshPlaybackQueue()`: следующий трек меняется, текущий не прерывается.

### AudioEngine

Обёртка над `AVAudioPlayer` для одного текущего трека. Открывает и закрывает security-scoped доступ, передаёт громкость и баланс, считает битрейт по размеру файла, отдаёт уровни каналов. События делегата AVFoundation приходят как `nonisolated`, переносятся на главный поток и игнорируются, если декодер уже заменён другим треком. Модель получает их через `onFinish` и `onDecodeError`.

### Импорт, прогресс и отмена

Одновременно выполняется одна задача (`importing == true`). Назначение (очередь или плейлист) фиксируется до начала работы.

1. Модель создаёт `ImportJob` и публикует `ImportProgress` (название, готово, всего).
2. `MediaScanner` в фоне ищет файлы (`MusicFiles`), затем открывает их параллельно через `DispatchQueue.concurrentPerform`. Порядок результата совпадает с порядком файлов.
3. Отчёты о прогрессе прореживаются до 10 в секунду и передаются на главный поток.
4. Готовый результат применяется на главном потоке, только если задача не отменена и не заменена новой.

При обновлении папки известные файлы не открываются повторно: читаются только новые. Недоступная папка не очищается.

`cancelImport()` помечает задачу отменённой и сразу разблокирует интерфейс. Фоновые потоки останавливаются на ближайшем файле, их результат отбрасывается, библиотека не меняется. В нижней панели во время импорта вместо счётчика треков показываются ход работы и кнопка «Отмена».

Ошибка создания security-scoped закладки не блокирует импорт: в локальной сборке без App Sandbox app-scope key может отсутствовать. Тогда сохраняется обычный файловый URL. Файл, перемещённый без доступной закладки, потребуется добавить заново.

### Drag and drop

`TrackDropDelegate` передаёт providers в `DropReceiver`. Внутренний перенос определяется по **точному** идентификатору `local.vibewave.track` в `registeredTypeIdentifiers`. Внешние файлы загружаются как `public.file-url`; порядок результатов сохраняется независимо от времени загрузки (`DispatchGroup` и защищённый `NSLock` буфер).

- Внутри одного раздела меняется порядок.
- Между сохранёнными плейлистами запись переносится.
- Из очереди и из папки трек копируется; исходная запись остаётся.
- В папку извне ничего не переносится.
- Конфликт дублей не удаляет исходную запись.
- Перетаскивание папки из Finder добавляет её в раздел «Папки».

### Окно и интерфейс

`VibeWaveApp.swift` запускает NSApplication, меню и единственный `RetroWindowController`. `RetroWindow.swift` ограничивает AppKit-часть рамкой и заголовком, а содержимое размещает в NSHostingView.

`RetroWindow` — borderless-окно с изменяемым размером, способное стать key/main. Пробел вне текстового поля переключает воспроизведение. Заголовок содержит настоящие NSButton с доступными именами и действиями сворачивания, разворачивания и закрытия. Перемещение передаётся Window Server через `performDrag(with:)`. Положение и размер сохраняются механизмом frame autosave.

`ContentView` собирает окно: заголовок, `ClassicPlayerPanel` (табло, бегущая строка, kbps/kHz, моно/стерео, индикатор уровня, громкость, баланс, позиция, кнопки ⏮ ▶ ❚❚ ■ ⏭), плейлист и при необходимости боковую панель библиотеки. `WindowSizer` расширяет окно при открытии библиотеки и сужает при закрытии. `TrackTable` показывает выбранный плейлист или папку, «Общий список» или «По плейлистам». `TrackRow` — строка без Button: щелчок запускает трек, протяжка переносит строку. Системные файловые диалоги и контекстные меню остаются нативными.

## Сборка и проверки

`VERSION` — единственный источник версии. `Resources/Info.plist` — шаблон; скрипт подставляет версию и копирует ресурсы в новый временный bundle. После подписи и проверки новая сборка заменяет старую.

`scripts/build-app.sh` собирает через SwiftPM, а без PlatformPath — напрямую через `swiftc`. `scripts/check.sh` компилирует все исходники приложения, кроме точки входа, вместе с `Checks/RegressionChecks.swift`. Списки файлов берутся по маске, поэтому новые исходники попадают в обе сборки автоматически.

CI (`.github/workflows/ci.yml`) на `macos-15-intel` выполняет `swift test`, сборку `.app`, проверку подписи и `scripts/check.sh`.

`dist/` и `.build/` — производные артефакты, они не входят в Git. Исходные изображения и аудиофикстуры входят в репозиторий: они нужны для воспроизводимой сборки и проверок.
